# 小糖人之家

小糖人专属的本地优先、无审查的多模态 AI 聊天客户端。
核心是小糖人角色（大诗音、小诗音、小白、小红薯头），并配有 Live2D / 3D 可视化形象。

> 本文档讲「怎么跑起来」**并记录当前实际实现了什么**。
> [`项目要求.txt`](./项目要求.txt) 是早期设计稿（编号 §x.y 的出处），部分内容已过时 ——
> 与代码冲突时**以本文档和代码为准**。

---

## 技术栈

- 前端：React + TypeScript + Vite + Tailwind CSS
- 后端：FastAPI（Python 3.10+）
- 存储：SQLite（人设 / 世界书 / 越狱设置 / 聊天记录 / 记忆 / 画廊；库文件 `backend/data/xiaotangren.db`，已加入 .gitignore）
- 模型接入：OpenAI 兼容接口（商业 API / 第三方中转 / 本地 Ollama 通用）

## 快速开始（本地开发）

### 1. 后端

```bash
cd backend
cp .env.example .env      # Windows 下：copy .env.example .env
# 编辑 .env，填入你的 model_base_url / model_api_key / model_chat / model_vision
uv sync                   # 安装依赖
uv run uvicorn app.main:app --reload --port 8000
```

### 2. 前端

```bash
cd frontend
npm install
npm run dev               # 默认 http://localhost:5173
```

前端已配置代理，把 `/api` 转发到后端 `http://127.0.0.1:8000`。
打开 http://localhost:5173 即可聊天。

### 手机 / 其他设备访问（同一 Wi-Fi 或校园网）

前端 dev server 已监听所有网卡（`server.host: true`），所以**同一局域网内的手机**可以直接打开。
启动时脚本会打印可用地址，形如：

```
http://192.168.x.x:5173
```

把那串地址在手机浏览器里打开即可（**保持电脑上两个服务开着**）。

> 代理发生在电脑本机，手机只跟 Vite 打交道，`/api` 由 Vite 转发给后端 —— 所以
> 手机侧**不需要**、也**不应该**直连 `:8000`，后端仍可只绑 `127.0.0.1`。
> 若打不开：确认手机与电脑在同一网段、电脑防火墙放行 5173、路由器未开启「AP 隔离」。
> ⚠️ 该配置面向本地/局域网开发，**请勿把 5173 直接暴露到公网**。

**手机端界面（§28，布局固定）**：窄屏（<768px）聊天页切为**底部 Tab**，一次只显示一栏，
桌面端仍是三栏并排。底部导航固定为四个按钮，**从左到右顺序不变**：

| 按钮 | 内容 |
|---|---|
| 💬 消息 | 电脑端「聊天 → 最近聊天」的会话列表。列表尾部还有「🏠 糖人小窝」入口（从这里可路由进小窝）；点会话直接进聊天。 |
| 🐾 聊天 | 当前会话的对话框（消息列表 + 底部输入栏）。 |
| ⚙️ 设置 | 电脑端聊天顶栏右边那一排功能（§28 起全部迁到这一栏）：👥 成员 / 🔍 提示词 / 📞 通话 / 🪄 自动记忆 / 🖼 画廊 / 🗑 删除 / 🧠 记忆 / 🎨 生成 / ⚙ 模型设置，以及「常规 / 🔓 无审查」通道切换。 |
| 🔒 隐私 | 电脑端的「私人空间」：自己的身份档案页。 |

聊天页顶栏左侧的 **◁ 返回按钮**：在群聊和每个私聊里都在最顶栏左上角，点它回到「消息」栏。
聊天界面**顶栏下面那一栏路由角色介绍的部分已去掉**（§28）—— 头像/署名点击即可进角色介绍，不重复。
**布局未经允许不要改**。

手机端的画廊 / 存储管理（§9.4 / §15.3）：立绘浮层的动作行、存储清单里的小图都按 767px 断点收窄，
动作按钮在窄屏上换行铺开、清单里的缩略图缩到 36px，面板内边距一并收紧，避免横溢。

启动脚本打印的地址里，`169.254.x.x` 是系统自分配的无效地址、`172.x` 多为虚拟网卡
（WSL/Hyper-V），**用手机所连网段对应的那个 IP**。

**原图清理**在「设置 → 存储管理」（电脑端在右侧状态栏），生图窗口不再提供删除入口。
打开后会**列出当前会话落盘的每个原文件**（图片 / 视频，带尺寸和被引用次数），
**勾选你要删的那些，再点删除、二次确认** —— 只会删掉勾中的，不会再出现「一点就全清空」。
删原图会连带删掉它的缩略图、它在画廊里的收藏和对应照片记忆；聊天记录保留，但那张图会变成打不开的空图。
缩略图是原图的衍生物，不单独列出（删原图时按 hash 一并回收）。
后端也拒绝未指定会话、未勾选文件或未带确认标记的删除请求，旧页面不能再以空参数清空全部原图。

**回复突然结束**时，界面会提示上游返回的长度限制、内容过滤或连接中断，并保存已收到的文字。
模型设置中的回复上限 `0` 表示使用上游默认值，并非无限长度。历史消息未记录结束原因，无法据此追溯当时的具体原因。

### 在外用流量访问（公网穿透）

上面那些 `192.168.x.x` 只在同一 Wi-Fi 下有效。想用手机流量、在外面随时打开，
用 **Cloudflare Tunnel 临时通道**：不需要账号，一条命令，给一个 `https://` 地址。

```bash
# Windows：双击
start-tunnel.bat
```

脚本会自动探测端口（开着 `npm run dev` 就用 5173，跑 Docker 一体化就用 8000），然后打印一个
`https://xxxx-xxxx.trycloudflare.com`，**手机上直接打开这个地址即可**，不用连 Wi-Fi。

首次需要 `cloudflared`：从
[releases](https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe)
下载一次（约 20 MB，无需注册），存成仓库根目录下的 `cloudflared.exe`，脚本会自己找到。
不想装它也可以用 npm：`npm i -g localtunnel && lt --port 5173`。

> ⚠️ 通道一开，**任何拿到这个网址的人都能访问你的家**（含模型 Key 的代理调用）。
> 地址是随机串、关掉窗口即失效，但仍别把链接发到公开地方；用完随手关。
> 想要固定域名 + 访问控制，就注册 Cloudflare 账号做具名隧道。
> 🔒 顺带解决一件事：`https://` 才是**安全上下文** ——
> 手机上的「🎤 按住说」在 `http://192.168.x.x` 下会被浏览器直接拒绝（§16.17），
> 走隧道后麦克风才能用。

## 模型配置

后端配置在 `backend/.env`（本地敏感信息，已被 .gitignore 忽略，不会提交）：

```
MODEL_BASE_URL=https://vsllm.cc/v1   # OpenAI 兼容端点（/v1）
MODEL_API_KEY=sk-...                  # 你的 key；本地 Ollama 填 ollama
MODEL_CHAT=gemini-3.8-flash           # 文字聊天模型
MODEL_VISION=gemini-3.8-flash         # 看图模型
MODEL_IMAGE=                          # 生图模型（vsllm 无生图通道，需另配中转）
IMAGE_BASE_URL=                       # 生图中转地址（留空 = 用 MODEL_BASE_URL）
```

聊天页「⚙ 模型设置」也可在浏览器里直接填（base_url / key / chat / vision / 生图模型），
存入本地浏览器；Key 留空 = 走服务端 `.env` 里的 key。

支持任意 OpenAI 兼容来源：

| 来源 | `MODEL_BASE_URL` 示例 |
|---|---|
| 商业 API | `https://api.openai.com/v1` |
| 第三方无审查中转 | 中转方提供的 `/v1` 地址 |
| 本地 Ollama | `http://localhost:11434/v1`（key 填 `ollama`） |

### 双通道：常规 / 无审查（NSFW）

聊天页头部有 **「常规 / 🔓 无审查」** 两个 chip，一键切换当前通道（切换即作用于聊天、看图、自动记忆提炼、画廊「自动描述」；生图本轮仍走常规通道）：

- **常规通道**：上面那组 base_url / key / chat / vision，日常对话与看图最稳。
- **无审查通道**：在「⚙ 模型设置 → 🔓 无审查通道」里单独填一份 base_url / api_key / chat 模型 / vision 模型，指向第三方无审查中转或本地无审查模型。
  - 字段**留空 = 沿用常规通道**（例如只填地址和模型名，key 复用同一把）。

后端无需为第二条通道改路由 —— `providers/openai.py` 是无状态的，每次调用都由请求显式带上 `base_url/api_key/model`。切到无审查通道时前端额外带 `uncensored: true`，后端会在 System Prompt 末尾追加「🔓 无审查专属规则」（在「规则 / 越狱」页单独编辑，可用「✨ 填入推荐预设」一键填一版角色扮演向范例）。

## 语音（TTS）

多引擎 TTS，**先选引擎、后选音色**（聊天页右栏「🗣 语音」）：

| 引擎 | 说明 | 音色 |
|---|---|---|
| `edge` | 微软在线 Neural TTS（edge-tts，免费、需网络） | 晓晓（默认） |
| `piper` | 本地离线轻量合成（piper-tts + onnx，无需网络、低算力友好） | 华燕 / 小雅 / 超文 |

> GPT-SoVITS 的占位按钮**已按用户要求删掉**（当时只是个"未安装"的死按钮）。引擎表里没有它，请求它返回 400。以后真装了再加回来。

> ⚠ **edge-tts 要 ≥ 7.3。** 7.2.x 会在 WebSocket 握手时被微软挡回来
> （`403 Invalid response status`，`wss://speech.platform.bing.com/.../edge/v1`），
> 表现就是 `/api/voice/tts` 一律 **502**、QQ 桥「语音没合成出来，这条改打字」。
> 2026-10-14 本机从 7.2.8 升到 7.3.1 后恢复正常（同一个 token、没走代理，纯粹是版本）。
> 升级：`uv pip install --python backend/.venv/Scripts/python.exe -U "edge-tts>=7.2"`，
> **改完要重启后端**才会生效。

引擎与音色**选择会被记住**（存浏览器），刷新 / 切会话不会弹回默认。
edge 连点朗读时后端会做 250ms 最小间隔节流 —— edge-tts 每次合成都要新开 WebSocket，前一条没关干净时新的一条会卡几秒。

- `GET  /api/voice/engines` —— 引擎列表
- `GET  /api/voice/voices?engine=xx` —— 某引擎的音色
- `POST /api/voice/tts` —— `{text, engine, voice}` → 音频（edge=audio/mpeg，piper=audio/wav）

右栏开关：「🔊 朗读/停止」（最近一条）、「🎙 自动朗读」（每条回复自动播）。
同一时刻只会有一条语音：新朗读会作废在途旧请求并停掉上一条，「⏹ 停止」可立即停下。

piper 音色文件放在 `backend/data/tts/piper/*.onnx`（约 60MB/个，已 gitignore，不随仓库提交）。
**换机器 / 新 clone 后需先下载一次**：

- Windows：双击 [`download_piper_voices.bat`](./download_piper_voices.bat)
- Linux / macOS：`./download_piper_voices.sh`

脚本默认走国内镜像 hf-mirror（可设 `PIPER_MIRROR` 换源）。下好后 `GET /api/voice/voices?engine=piper` 才会列出对应音色。

## 记忆 RAG（三层记忆）

记忆检索走本地 embedding，默认用 `BAAI/bge-small-zh-v1.5`（约 100MB，CPU 可跑）。
模型文件同样**不进 git**，换机器 / 新 clone 后需先下载一次：

- Linux / macOS：`./download_embedding.sh`
- Windows：`./download_embedding.sh`（Git Bash / WSL 均可；纯 `curl` + `git-lfs` 回退）

脚本默认走 hf-mirror（可设 `HF_MIRROR` 换源；可设 `EMBED_MODEL` 换模型），把模型下到 `backend/data/models/embedding/`。
下好后记忆 RAG 立刻生效。若本地模型没下（或缺依赖），可在 `.env` 里切云端 embedding：

```
EMBED_ENGINE=cloud                  # local（默认）| cloud
EMBED_BASE_URL=https://vsllm.cc/v1  # 留空 = 复用 MODEL_BASE_URL
EMBED_CLOUD_MODEL=text-embedding-3-small
# key 复用 MODEL_API_KEY
```

### ⚠ 换 embedding engine 需重建向量库

本地小模型与云端 `/v1/embeddings` 产出的向量**口径不同**（不同模型向量空间不同，余弦相似度不可比）。
换 engine 后请务必清空并重建记忆索引，否则检索会乱掉（见 [`项目要求.txt` §16.6](./项目要求.txt)）。
最简单方式：删掉 `backend/data/xiaotangren.db` 里的 `memories` 表，重新触发记忆存储即可。

## 生图

四个**可插拔引擎**，聊天页「🎨 生成照片」浮层顶部一键切换（选择会记住，存后端）：

| 引擎 | 状态 | 说明 |
|---|---|---|
| `local` 本地 ComfyUI | ✅ 可用 | 3050 4GB 本地跑，免费无限。填 `COMFYUI_URL` 即可 |
| `cloud` 云端 ComfyUI | ✅ 可用 | **与本地同一套协议**，只是地址不同（如 CNB 转发地址）。填 `COMFYUI_CLOUD_URL` |
| `thirdparty` 第三方 API | ✅ 可用 | 任意 OpenAI 兼容 `/images/generations` 中转 |
| `novelai` NovelAI | 🚧 插槽 | 协议不兼容 OpenAI，需独立适配器，本轮未实接 |

- `GET  /api/images/engines` —— 引擎列表（`ready` 为**实时探测**结果）+ 当前选中项
- `POST /api/images/engines/select` —— `{id}` 记住选择
- `POST /api/images/generate` —— 按当前引擎出图，结果**直接落附件库**（`source="generated"`），返回 `{images: [{id, orig, thumb}]}`

浮层里可调：提示词、负向提示词、尺寸、张数（上限 4）、步数、CFG、seed（后四项在「更多参数」里，留空 = 用工作流自带值）。
出图后点 **⤓** 下载、**⭐** 存入画廊（同聊天图片那条路）。

### 外观提示词自动拼装

浮层的提示词框会按**当前会话在场角色的当前形态**（§20）自动拼一句外貌描述（发色 / 发型 / 瞳色 / 服装…）。
「自动拼装外貌」可关；你手改过的内容**不会被覆盖**（换角色 / 换形态时会重拼，但你写的东西留着），点 **↺ 重置** 可恢复当前形态的自动版本。

### 连本地 ComfyUI

在 ComfyUI 里画好工作流 → 菜单 **`Workflow` → `Export (API)`**（旧版点齿轮开 Dev Mode 后是 **`Save (API Format)`**）
→ 导出成 `*_api.json`（形如 `{"3": {"class_type": "KSampler", "inputs": {...}}, ...}`）。
**导成带 `nodes` 数组的普通格式是错的**，那是有向图 UI 序列化，后端识别不了。

把它放进 `backend/.env`：

```
IMAGE_ENGINE=local
COMFYUI_URL=http://127.0.0.1:8188       # ComfyUI 默认端口
COMFYUI_CLOUD_URL=                      # 云端转发地址（填了就能切 cloud 引擎）
COMFYUI_WORKFLOW=                       # 留空 = 用 backend/examples/comfyui/ 里的内置示例
COMFYUI_TIMEOUT=180                     # 单张图总预算（秒）
```

不填 `COMFYUI_WORKFLOW` 就用内置的 SD1.5 示例（`backend/examples/comfyui/sd15_basic.json`）——
**用之前记得把里面的 `ckpt_name` 改成你本地实际有的模型名**，否则 ComfyUI 会直接报节点错误。
示例与导出说明见 [`backend/examples/comfyui/README.md`](./backend/examples/comfyui/README.md)。

工作流里的节点**按拓扑定位，不按 id**：正向提示词取 `KSampler.positive` 连着的 `CLIPTextEncode`、
宽高取 `latent_image` 连着的 `EmptyLatentImage`、出图取 `SaveImage` ——
所以你换模型、加 LoRA、改组节点 id 都不会崩（详见 [`项目要求.txt` §16.13](./项目要求.txt)）。

> 云端各种算力方案仍在逐个试（CNB 按核计费不合算 / vast.ai 需信用卡 / AutoDL 禁 NSFW / NovelAI 待适配），
> 引擎抽象已就位，**试出哪个就填哪个地址，不用改代码**。

### 第三方生图 API

`IMAGE_BASE_URL`（留空 = 用 `MODEL_BASE_URL`）+ `MODEL_IMAGE` 填一个支持 `/images/generations` 的中转即可
（当前 vsllm 中转没有生图通道）。也可在聊天页「⚙ 模型设置」里临时填。

## 画廊与照片记忆

聊天里的图片气泡右上角点 **⭐** 存入画廊（「🖼 画廊」按钮可管理）。画廊图 = 图片 / 视频文件 + 一段文字描述。

### 多选上传：照片和视频一起挑（§9.4）

画廊的「**＋ 上传图片 / 视频**」（聊天 🖼 浮层、角色介绍页、糖人小窝三处都有）支持**一次多选**，
照片和视频可以混在一批里，选完一次全传：

- 前端走 `POST /api/attachments/batch`（multipart，一次多个文件），后端**按文件类型分流**：
  图片 → 落盘 + 生成缩略图；视频 → 原样存盘、**不抽帧**，靠浏览器 `<video>` 直接播。
- **单个文件失败不拖垮整批**：超限 / 类型不支持的记进 `errors`，其余照常入库，界面会提示「N 个成功、M 个失败」。
- 视频上限 **100 MB**（一般是 30 秒出头那种），容器认 `.mp4 / .mov / .webm / .mkv / .avi`；
  图片上限仍是 20 MB。那条链路（`/api/media/video/*` 抽帧看图）门槛更紧（15 秒 / 50 MB / ≤8 帧），
  两条互不影响 —— **这里是「存得住 + 播得出」，那边是「送给模型看」**。
- 画廊里的视频带 **▶** 角标，鼠标移上去会静音预览，点开是能播的 `<video controls>`（不再只显示一张缩略图）。
- 视频**不支持「自动描述」**（vision 模型读不了视频），点它会提示「请手写一句」；描述、归属、私密、进记忆这些照常。

### 点开就能改：介绍页立绘浮层也带画廊动作（§9.4 / §19.13）

从**角色介绍点开立绘 / 画廊图**，浮层不只是看大图 —— 如果这张图也收进了画廊，
直接摊开画廊那一整套按钮：**自动描述 / 编辑 / 进小糖人记忆 / 🔒 私密 / 归属**，
没有描述时显示「（还没有描述，点『自动描述』或『编辑』写一句）」。
不用再跑去聊天的 🖼 画廊里翻同一张图。没收藏过的立绘仍只是看大图。

### 画廊是私人的：按归属分开放（§9.4.1）

每张画廊图有一个**归属**，决定它「属于谁」：

| 归属 | 看到它的地方 |
|---|---|
| **家 · 共用** | 「糖人小窝」的「共同回忆」 |
| **某个角色**（如大诗音） | 那个角色的**介绍页**下方 |

- **自动归属**：私聊里 ⭐ 收藏的图，自动归给对话里的那位；群聊 / 导入会话收藏的归「家 · 共用」。
- **手动改**：画廊面板里每张图带一个归属下拉，随时改到别的角色或「家 · 共用」——
  **不做自动识别，分类由你自己定**。聊天里的 🖼 浮层还是全量视图（带归属筛选），是「整理」的地方。
- **自己上传图进画廊**：画廊面板有「**＋ 上传图片 / 视频**」（可多选）。在别的地方生的图也能收进来，成为记忆的一部分 ——
  不再只能「先发出去再收藏」。
- **照片记忆跟着归属走**：私人画廊的描述进 `personal/<角色>` 桶，**只有她本人在场时**才检索得到
  （群里聊到这个话题，其他小糖人不会知道）；家共用的描述进 `home` 桶。改归属会连带重建记忆。

### 画廊分层：公开 / 私密（§26 防瞥屏）

每张画廊图可以标成**私密层**（`private: true`），防的是**别人瞥屏**，不是瞒着小糖人：

- **私密只影响显示，不影响记忆** —— 该进她照片记忆的描述照常进。
- **公开层照常铺开**；私密层收在画廊下方**一条折叠行**（「🔒 私密 N 项」），
  默认收起、点了才渲染，且**展开状态不持久化** —— 刷新页面自动收回，私密图不会一进页面就摊在屏幕上。
- 公开层空了会提示「这里的图都收在私密层了（下面那条展开）」，而不是显示成空白。
- 写入 / 切换走 `PATCH /api/gallery/{id}` 的 `private` 字段；`GET /api/gallery?private=true|false` 只取一层，不传 = 两层都取。

### 照片记忆

- **照片记忆（A 方案，默认）**：画廊图的文字描述会作为一条记忆走 §9.2 的 embedding/RAG，
  聊到相关话题时注入「你有一张照片：〈描述〉」。每条画廊图带「是否进小糖人记忆」勾选
  （默认进，可关掉过于私密的）。
- **照片记忆（B 方案，留口子）**：多模态 embedding（中文 CLIP），图片与文字进同一向量空间 ——
  目前只留 Provider 接口占位，默认不用。
- 描述可手写，也可点「自动描述」让 vision 模型看图写一句。

接口：`GET/POST /api/gallery`（`GET` 支持 `?owner=` / `?private=` 过滤）、`POST /api/gallery/{id}/describe`、`PATCH/DELETE /api/gallery/{id}`。
上传走 `POST /api/attachments/batch`（multipart，`session_id="gallery"`，图片 / 视频混传）落盘后再 `POST /api/gallery`（带 `kind`）；
旧的单文件 `POST /api/attachments`（data URL）仍保留给聊天贴图那条路。
画廊表新增 `kind` 列（`image` / `video`），老库升级时 `_migrate` 自动补列、老行全部落成 `image`，行为不变。

## 视频：抽帧后看图

聊天可以**发视频**（输入框的 🎞 按钮，或 `Ctrl+V` 粘一个视频文件）。做法和「看图」是同一套，只是多了一步本地预处理：

1. 前端把视频传给 `POST /api/media/video/analyze` → 后端用本机 **ffmpeg / ffprobe** 探测时长并抽帧。
2. 抽帧结果挂在输入框上方预览，可以配一句话、也可以直接发。
3. 发送走 `POST /api/media/video/chat`：抽好的帧以「多图 + 文本」送**视觉模型**，SSE 流式回复。

**完整视频绝不发给模型** —— 只有抽出来的帧进模型，token 有硬上限：

| 限制 | 值 |
|---|---|
| 最长时长 | 15 秒 |
| 最大体积 | 50 MB |
| 抽帧上限 | ≤ 8 帧（约每 2 秒一帧） |
| 支持格式 | mp4 / mov / webm / mkv |

- **依赖 ffmpeg / ffprobe**：没装会直接返回 503 并明确报错，**不会**自动改动系统环境。
- **帧不落库**：消息里只存第一帧当封面，抽出的其余帧只在本轮内存里 —— 刷新后回退成一张首帧。
- 视频消息的**重新生成 / 编辑重发不支持**（和看图轮同理：帧没有落库，重发时拿不到）。

## 删除聊天记录（真删）

聊天页在**任意已落库的消息**上**右键**：

- **删除这条** —— 直接删
- **多选…** —— 进入多选模式，每条消息左侧出现复选框，顶部浮出「已选 N 条 · 删除 · 取消」

> 多选模式下**点这条消息的任意位置**都能勾选，不用非得去点那个小复选框。

改自己的话用气泡下方那个显眼的「**✎ 编辑**」小按钮（§19.15，以前藏在右键菜单里没人发现）——
改完这条，它**之后的所有对话都会被删掉**并重新生成（Gemini 式；只对纯文字的自发消息开放）。

也可以点顶部的「🗑 删除」按钮直接进多选模式。**这是真删，删掉找不回来**：

1. 消息记录从库里删掉
2. 图片若**再没有别的消息引用**，连带删掉画廊里的收藏（含它的照片记忆）和磁盘上的原图 / 缩略图
3. 删除前的确认框会如实告诉你「N 条记录 + M 张图片 + 画廊 K 张」

同一张图被两条消息共用时，只删其中一条 → **图片文件会保留**，另一条照常显示。

**你自己的消息和小糖人的回复都能删**；流式生成中禁用删除。

### 小窝大脑 API（§9.6 通用外设接入层）

小窝的定位是「全家共同的**放松 + 玩耍**入口，以后会集成很多功能」，所以模型 API 单独管一套：

- **跟聊天分开** —— 聊天页那份 `xiaotangren.config` 是聊天用的；小窝走**后端** `/api/nest/api-config`。
- **两层配置**：一份「**全局默认**」（**默认带视觉路**，看图 / 看视频抽帧）+ 每个功能可**单独覆盖**任意字段。
  功能留空 = 用全局默认；想彻底不用视觉，勾掉那个功能的「用视觉」即可（`needs_vision=false`）。
- **每个功能是独立项目**：本体只提供大脑 API（人格 / 记忆 / 模型调用 / 命令队列），
  功能各自的逻辑（游戏 Mod、B站抓取、QQ 桥）在 `features/<folder>/` 里，**各自单独 git**、不进本体仓库。
  本体能**替你在小窝里按一下启动键**（`POST /api/nest/features/{id}/run`）：命令串由后端按
  `features_registry.py` 里的 `runner` 白名单拼出，前端传不了任意命令；日志落 `backend/data/nest_runs/`。
- **人设只有一个来源** —— 角色介绍（`/api/characters`）。功能项目**不复制人设**，只传 `character_id`，
  人格由大脑组装；本地最多留一份「名字兜底表」，防止连不上大脑时日志里全是 id。
- **记忆隔离** —— 功能攒下的记忆按功能命名空间存（`feature_id`），**不会漏进日常聊天**；QQ 这种「想让它记住」的可以主动不隔离。
- **让模型动手，但边界在功能里** —— 功能可以说「给我几个本地工具声明」（`POST /api/nest/tool-turn`），
  本体把声明转给模型、再把模型的**决定**原样回给功能 —— **本体一个动作都不执行**。
  真正的白名单和沙箱在功能那一侧（只有它知道沙箱在哪）。QQ 桥的示范：默认关；开了之后
  ① 只有大老大的消息能触发 ② 只能跑代码里写死的那几个只读动作 ③ 路径必须落在划定的目录里
  ④ 删除 / 关机 / 格式化这类**写死在代码里永远拒绝**，配置改不动。
- **两条通用能力**：`POST /api/nest/feed`（功能把产出推给小窝，见「📬 小糖人找到了什么」）；
  `POST /api/nest/chat` 支持 `images`（data URL ≤8 张）—— 有图走该功能的**视觉路**，没图走普通路。
  > 📺 这就是「一起看」的口子：视频抽成 ≤8 帧传进来即可；实时逐帧 token 太贵，按 §9.6.3 暂不做。

> 📌 功能本身**不造假功能**：注册表里 `planned` 的点了会说明「实现是独立项目」，`available` 的才有真入口。
> 协议见 [通用外设接入层](./docs/nest-integration.md)（旧的[游戏专用协议](./docs/game-integration.md)仍兼容）。

**Unity 互动小家的路径**在 `.env` 里配（不配就用代码里的默认值）：

## 🐻 私人空间：个人档案身份系统

**你自己的几份身份卡**都在这里。当前用哪份身份说话，小糖人们对你的反应就跟着变
—— 和酒馆里的个人档案系统是同一件事，**用不同身份对话才有趣**（§22）。

顶部导航的 **「🐻 私人空间」** 复用角色介绍页的全部内容（介绍 / 立绘 / 形态 / 词条 /
世界书 / 专属画廊），只是把数据源换成**你的身份档案**，成员切换行换成**一排身份卡片**。

两套身份：

| 身份 | 是什么 | 别人眼里的存在感 |
|---|---|---|
| **大老大** 🐻 | 小糖人之家的主人（默认身份，不能删） | `asCharacter: true` —— 你切到别的身份时，他会作为可聊角色现身 |
| **汐子** 🌊 | 大老大的**性转独立体**，同一个人、以女生的身份独立走出来 | `asCharacter: false` —— 永远只当身份，不进角色介绍 / 群聊 |

- **卡片交互**：点卡片 = 看档案；点旁边那个 **「成为」** 按钮才真的换视角
  ——「不点就不成为」，只是想看看时不会被顺手换掉身份。
- **视角切换是全局一处**：私聊群聊一起走，存在后端 `settings.active_persona_id`。
- **聊天记录每个身份各自一条**：默认身份不加前缀（老历史一条不丢），
  其他身份是 `<personaId>@<sessionId>`。**一个身份说过的话，另一个身份看不到。**
- **但记忆不随视角变**：小糖人们的记忆**完全独立于用户视角**（仍按 `(bucket, char_id)` 存）。
  汐子想知道大老大的事，只能当面问他 —— 没有自动共享，这样才自然。
- **档案上还有个 `relation` 字段**（「与大家的关系（喂给模型）」）：它**单独存在**，
  不写进 `about`、也不走词条 —— "我是谁"和"这个人什么性格"是两码事。
  它会在组装 Prompt 时注入，替代以前写死的「哥哥/姐姐」。
- **加新身份**：私人空间里点 **「＋ 新身份」**，新建即进编辑，词条跟小糖人一样全可改。
  新档案默认**不当**可聊角色，想让她现身就去编辑面板把开关打开。

**大老大不会自动出现在群聊里** —— 单模型分饰多角时，把用户自己列进「在场角色」会让模型
以为要替用户说话，和你亲手发的消息打架（§8.5 的老结论）。所以 `personasAsCast` 会**排除
当前身份**，只把 `asCharacter: true` 的**别人**放进去。

老库启动时逐条幂等补种（已有档案绝不被覆盖），并给老档案补上缺的新字段
（`_backfill_profile_fields`）。删掉的档案会记墓碑（`settings.deleted_profiles`），
**不会被种子复活**。想加新身份也可以直接 `POST /api/profiles`。

### 我的档案（§23）：这份身份的私人笔记本

私人空间里、身份卡下方还有一块 **「我的档案」** —— 这是**你**记录自己的地方（喜好 / 日常作息 /
年度目标…），跟小糖人的角色独占世界书是两回事。

- **存的是真的 Markdown 文件**，不是数据库里的 blob：
  `backend/data/self_profile/<身份id>/*.md`，外加一个跨身份共享的 `_shared/` 目录
  （放「账本」这类任何身份都该看到的东西）。
- **每个区块 = frontmatter + 正文**：

  ```markdown
  ---
  title: 喜好
  inject: true                 # true = 聊天时注入给模型
  visible_to: all              # all | [dashiyin, xiaoshiyin, ...]
  created_at: 2026-10-05
  ---
  正文……
  ```

- **`inject`**：打开后，聊天时这段内容会注入进 System Prompt（面板上那个「聊天时注入」勾选）。
- **`visible_to`**：限定这段只给哪些小糖人看（默认所有人）。留空 / `all` = 全部可见。
- **正文就是 textarea 直写** —— 不接 Markdown 渲染库，跟项目其他面板一致（所见即所得地存原文）。
- **导出**：面板右上角「📦 导出」把该身份（含 `_shared`）的全部 `.md` 打包成 zip 下载
  （`GET /api/self/export`）。

接口：`GET /api/self/status?persona_id=`、`GET/PUT/DELETE /api/self/{persona_id}/{filename}`、
`POST /api/self/{persona_id}`（新建）、`GET /api/self/export?persona_id=`。

> 📌 **计划中的 Obsidian 集成**（尚未实现）：因为档案本就是磁盘上的 `.md`，
> 以后打算让这些文件能直接指向 / 同步到一个 Obsidian 库（用 Obsidian 编辑，小糖人这边读同一批文件）。
> 目前只是「文件格式对得上」，同步功能**还没做**。

## 聊天手感与调试工具（§24 / §25 / §27）

### 看提示词（§24）：这条消息实际发出去的是什么

聊天页的 **「看提示词」** 浮层调 `POST /api/chat/preview` —— 后端**只组装、不调上游**（零 token 消耗），
把这次真正要发给模型的内容原样摊开：system（人设 / 世界书 / 自我档案 / 记忆注入 / 无审查规则）+ 外发历史。

> **改完档案 / 世界书不生效时先看这里** —— 一眼就能确认某段到底进没进 system，不用猜。

### 群聊阵容（§25）：谁在群里、谁先退场

**阵容面板**改「默认群聊里有哪些角色」，存在后端 `settings.group_roster`（复用 settings，**不新建表**）：

- **「不在场」≠「删除」** —— 私聊一条不少，只是暂时不让她在群里插话。
- **阵容改了，人设块跟着改**：后端按阵容重新组织人设块，其余逻辑零改动；
  另有一道「历史层清洗」（`_strip_absent_speakers`）兜底，把不在场角色以前说过的话从上下文里摘掉。
- ⚠ **至少留 1 人**：空阵容会被当成「没设置」回退成全员在场，反而更糟，所以前端直接拦住。

### 注入条数 / 不在场不渲染 / 等待提示（§27）

- **注入条数可调**：模型设置里的「注入条数」（`historyLimit`，存 `localStorage` 的 `xiaotangren.config`，默认 **20**）
  控制外发历史截断长度 —— 组装 `messages` 前只留最近 N 条，`0` = 不限制。带 10 / 20 / 50 / 不限制四颗快捷钮。
  **只截断发出去的副本**，界面与库里一条不少；老配置缺这个字段会自动补默认值。
  ⚠ 看图轮不带历史（`/api/images/chat` 本来就只发当前这张图 + prompt），这项对它无效。
- **不在场的人前端也不渲染**：阵容里被移出的角色，群聊视图里连历史发言都不显示。
- **等待提示**：生成中显示跳动三点 + 轮换文案，而不是一个静止的省略号。
