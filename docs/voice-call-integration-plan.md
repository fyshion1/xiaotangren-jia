# 自然语音通话接入方案

2026-10-19 初版方案。用户随后授权接入，实际首版与验证范围见 [voice-call.md](voice-call.md)：为沿用现有 HTTPS 隧道，传输改为同源 WebSocket PCM，没有引入 Pipecat/WebRTC；以下保留设计过程，实际能力以通话说明为准。目标来自用户对 Eidolon-SC 的实测：持续对话、准确识别中日英、情绪稳定；尤其避免轻微漏音。源码调研见 [eidolon-sc-voice-research.md](research/eidolon-sc-voice-research.md)。多语言支持是本项目的验收目标，不能由参考项目的中文/日语提示配置直接推定。

## 用户流程

在角色私聊点电话 → 首次允许麦克风 → 接通后持续说话 → 识别结束自动发送 → 角色边生成边说 → 用户开口可以打断 → 挂断后在原会话继续文字聊天。

通话层显示当前听到的话、角色回复和“正在听 / 正在想 / 正在说 / 正在重连”。保留麦克风静音、挂断、手动停止播放、文字输入。首版固定一位角色与当前身份；切换身份或角色需先结束通话。群聊、多角色抢话和唤醒词放到后续。

## 推荐架构

浏览器麦克风 → WebRTC → Pipecat → ASR Provider → 共用会话服务 → 分句朗读支路 → TTS Provider → WebRTC 音轨。

字幕、识别候选、回合状态、分段播放状态走 DataChannel。大脑继续使用现有模型来源、人设、世界书和记忆，不因进入通话改成另一个角色。通话可以增加短句、口语化的上下文指令，不覆盖角色卡与身份规则。默认中文回答；多语言识别和回复语言分别设置。

推荐先验证百炼流式 ASR + Fish Audio 流式 TTS；Soniox 为可选 ASR。用户体验到的识别、音色和延迟仍需用自己的账号、模型及网络实测。每位角色可绑定音色；只有配置好且有权使用的音色才启用。保留 Edge/Piper，并预留 sherpa-onnx 本地 ASR，沿用项目要求 §6 的 Provider 替换方向。Edge/Piper 模式应如实说明分句合成的等待特征。

## 现有代码接入点

| 位置 | 已有能力 | 需要的工作 |
|---|---|---|
| `backend/app/routers/session_chat.py` | `_session_turn` 共用会话、Prompt、身份、消息落库、记忆归档、delta 回调 | 提取可被 HTTP 与语音调用的服务，补充取消和中断结算，保持已有行为 |
| `backend/app/services/turn_coordinator.py` | 同身份/角色跨端回合协调 | 取消后释放 lease；一次模型回复持锁，不能整个通话一直持锁；插话优先终止旧回合再启动新回合 |
| `backend/app/routers/voice.py` | Edge/Piper、引擎与音色接口 | 保留旧接口，新增 Provider 层、通话配置与信令路由 |
| `frontend/src/components/ChatView.tsx` | 电话入口、原会话、手动朗读 | 接通话控制器，建立通话时停掉旧朗读，结束后同步后端消息，避免双重保存 |
| `frontend/src/hooks/useSpeechToText.ts` | Web Speech 按住说话 | 保留原入口；持续通话由新的控制器采集媒体音轨 |
| `frontend/vite.config.ts` | 同源 `/api` HTTP 转发 | 信令继续同源；若使用 WebSocket 路由需增加转发支持；WebRTC 媒体另行测试 ICE/TURN |

当前 `_session_turn` 在开始时保存用户消息，模型完整结束才保存助手消息；它没有为语音定义“已说部分”的中断落库。不能只连接 ASR 与回调后就认为完成集成。需明确回合取消状态、保留用户消息、助手的完整文本分段、播放进度及记忆结算。不能让模型已生成但被取消的整段内容默认为用户已经听到。

## 回合与音频完整性

- 标识使用 `call_id / turn_id / generation_id / segment_id`；取消后迟到的旧文字、音频和表情不得重新进入当前播放。
- 初次实现采用清楚的规则：用户有效开口时立即停播并取消旧回复；后续再完善“开口前补充并入同一回合”。不能在首版悄悄保留旧生成并与新回复混播。
- ASR partial 只作预览，final 才提交；用唯一 utterance 标识避免重复发送。临时结果和最终结果可能改写，不能简单累加候选文本。
- 模型文本走独立朗读分支，按句子和安全边界切分，尾句必须 flush；原消息保持原格式。Markdown、代码、HTML 卡片及括号动作描写需要明确朗读规则，不将标签逐字念出。
- 合成、缓冲、播放分离，保持分段顺序。合成结束不等于播放结束；已排队音频必须正常播完，只有用户打断、挂断或明确错误才丢弃，并标记原因。
- 设置有界队列及背压，弱网不允许无限积压。段尾超时、连接重建、取消竞态分别记录，不能用静默丢包掩盖错误。
- 麦克风启用浏览器回声消除等音频约束，并实测外放；只使用声音能量作打断依据容易让角色打断自己。有效语音/文字证据、服务商话语边界和停止播放时机需要平衡。

## 实施顺序和交付边界

1. **语音服务验证**：将运行时依赖放在独立可选安装组或独立语音环境；本项目当前运行 Python 3.14.7，而参考项目声明 Python 3.11+，须实测 Pipecat/aiortc/编解码依赖在 Windows 的安装兼容性，不能仅凭版本声明判断。用测试麦克风验证 ASR 中日英、Fish 音色与流式播放，记录真实延迟。
2. **接单角色完整通话**：抽取共用会话服务，接 Pipecat、信令、数据通道与通话层，完成自动发送、边生成边说、静音、挂断和打断。配置缺失显示具体缺项。服务失败显式告知，不暗中换声音或消耗另一套密钥。
3. **完成记录和故障语义**：断线、切页、挂断、中断、模型报错后都正确释放设备/任务/lease；聊天历史与记忆不重复，重新打开原会话可继续。合成/播放进度与中断状态分开保留，不把未播文本当作已听事实。
4. **手机与外网验证**：localhost 先跑通，再测试手机 HTTPS 和 ICE/TURN。现有 HTTP 隧道不能直接替代 WebRTC 媒体中继；如需 coturn，单独部署及配置。手机后台继续通话不作未经验证的承诺。
5. **扩展本地与表现层**：接本地 ASR、角色专属音色、桌宠动嘴和异步表情；这些不阻塞首版可用通话。

以上是工程依赖顺序，目标交付仍是点一次即可持续交谈。已有 §18 的“先做按住说话自动朗读”节奏与本方案不同，本轮保留原要求文本，待实施路线确定后统一更新。

## 验收

连续对话至少 20 轮，含中日英切换、句中停顿、短句、长回复、连续插话、咳嗽、外放、静音恢复与断线恢复；确认没有重发用户消息、旧音频回流、未打断时吞句首句尾、记忆重复提炼或跨身份串话。

分别测量 ASR final、首个可朗读分句、TTS 首音频、实际开始播放、插话到停声的时间，用中位数/高分位数观察瓶颈，不先承诺固定延迟。对漏音记录分段文本、收发音频字节数、取消原因和播放状态；调试数据应可关闭，默认不持久保存原始麦克风录音或密钥。

首版上线前需用户提供选择的服务凭证与角色音色配置。可以先完成代码与无密钥测试，但没有真实服务联调和手机测试时不能宣称达到参考网站的体验。
