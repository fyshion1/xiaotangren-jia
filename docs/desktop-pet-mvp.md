# Electron 桌面聊天 MVP

代码位于 `features/desktop-pet/` 独立 Git 仓库。本体仅增加功能注册、小窝配置卡片、普通会话 HTTP 呈现端接口和网页消息同步。Unity/DashiyinRoom 继续属于 D 盘素材与 Unity 项目，本次未改动。

## 本次范围

透明 Live2D、触摸动作与聊天气泡、桌面直接文字收发、窗口拖动、逐像素点击穿透、托盘退出、小窝启动/停止/配置。公开样例来自本机 assets，只读取，不复制进 feature 或构建产物。

默认大诗音的现有私聊；支持卡片选择其他现有角色或家庭群聊。角色与用户身份沿用本体。触摸不发起模型请求。未收到默认会话偏好的补充答复，先采用上述可配置默认值。

## 通用会话接口

这类呈现端是普通聊天的另一块屏幕，和独立外设 `/api/nest/chat` 的隔离会话不同。按用户明确要求，本次沿用普通聊天的记录与记忆桶。

`GET /api/chat/session?feature_id=desktop_pet&character_id=dashiyin&mode=single`

返回 `session_id, character_ids, persona_id, mode, title, items, configured`，不返回模型凭证。默认身份的键为 `single-<character>` / `group`，其他身份为 `<persona>@<session>`。返回最近 60 条记录。

`POST /api/chat/session/turn`：

```json
{
  "feature_id": "desktop_pet",
  "character_id": "dashiyin",
  "mode": "single",
  "session_id": "single-dashiyin",
  "text": "你好",
  "request_id": "唯一且可重试的发送编号",
  "auto_memory": true
}
```

服务端解析当前身份与成员、确认客户端预期会话未变，合并小窝大脑配置，调用普通聊天相同的人设/世界书/记忆 Prompt 组装器。消息与幂等记录同一事务提交。上游失败保留用户消息，重试同一个 request_id 不会重复写入；成功后重试返回已保存的回复。相同编号用于不同文字时返回 409。

自动记忆调用普通记忆服务，`feature_id=""`：私聊按个人桶、群聊按普通群聊规则，不维护桌宠自己的另一份记忆。群聊保留 speaker/text 分段。网页打开会话每 3 秒合并其他呈现端消息；本地流式生成期间暂停合并。

## 验证与限制

后端测试使用临时 SQLite，覆盖记录共享、身份切换、群聊成员、幂等重试、异常不泄漏上游详情、实际 Prompt 召回普通家/个人记忆并排除其他角色及外设隔离记忆。真实 Electron GUI 测试使用本机模拟回复，未向用户真实聊天写入测试消息。

已实测 Windows 下 alpha 透明处把系统鼠标点击传到下层窗口，人物与气泡接收点击，触摸开气泡、拖动、两个样例切换；普通/DPR2 截图检查、连续帧检查、强制终止 Python 后所有 Electron 子进程回收。小窝前端卡片也实际打开截图检查。

现已增加 `/api/chat/session/stream`：逐行 NDJSON `delta` / `done` / `error`，沿用相同落库和幂等流程；原 `/turn` 保持兼容。客户端按 request_id 接收增量，断线丢弃未落库草稿并可安全重试。

已增加自动朗读/重播/立即打断，复用 `/api/voice/tts` Edge/Piper。Electron 主进程获取音频，经受限 IPC 交给 AudioContext；分析实际音频能量，在 Live2D beforeModelUpdate 驱动 ParamMouthOpenY，停播关闭嘴型。收起气泡、隐藏窗口或新发送会停止播放并取消语音请求。自动朗读只针对桌面当前新回复，加载历史不触发朗读。

小窝卡片新增语音开关、引擎、音色、音量，以及字号、透明度、宽度和三套配色。真实 Edge 接口已成功返回 MP3，GUI 使用生成的测试 WAV 验证播放/打断，不依赖外网语音的稳定性。

本轮验证：42 项会话与小窝后端测试通过；前端类型检查、桌宠构建与资源边界测试通过；Electron 普通/DPR2 图检、增量文字先于生成完成、音频播放/打断、外观同步、失败重试和重载通过。原生鼠标回归覆盖透明处下层窗口收点击、身体命中、触摸开气泡及拖动。60 秒空闲渲染未报错，JS 堆约 31→34MB（不足以推断长期无泄漏）；包装器强杀后 5 个 Electron 子进程回收。

跨多屏不同 DPI、长时间使用耗电和不同驱动仍需后续实机验证。旧评估及其 103 份证据已迁回 `docs/desktop-pet-review/`；实际实现以本文与 feature README 为准。

## 显示器适配与形象选择补充

用户确认采用测试时的米黄色开衫、蓝色蝴蝶结女孩，即 Cubism 样例 Hiyori（不是 Neuro-sama 模型）。已在本体桌宠配置保存 `model=hiyori`，保留大诗音人设与现有私聊。

窗口现在监听显示器增加、移除和工作区/DPI 变化，按当前屏幕逻辑工作区重新适配宽高与位置，找回位于已断开屏幕的窗口；跨屏拖动结束后同步 Pixi 分辨率。几何测试覆盖左/上负坐标显示器、断屏后屏幕外位置、小于桌宠默认尺寸的工作区。当前电脑只有一块物理屏幕，DPR2 为强制缩放测试，不等同于真实双屏混合 DPI 热插拔。

本轮实际执行 180 秒 DPR2 持续渲染并反复隐藏/恢复，未出现渲染错误；JS 堆约 32.1→31.1MB，无持续上涨迹象，但不能据此宣称数小时运行无泄漏。普通 Electron GUI 还通过了把窗口放到屏幕外、触发显示器移除事件后自动找回的集成测试；模拟事件未改变操作系统显示器设置。

原生鼠标自动回归的偶发失败已定位并修正测试脚本：隐藏 Python 辅助进程窗口，避免 CDP 与系统鼠标混用，点击前校验实际光标位置及穿透标志，边缘拖动改为朝工作区内侧。修正后普通缩放和 DPR2 原生测试各通过一轮，覆盖透明处下层窗口收点击、人物命中、触摸开气泡及拖动；本次未修改产品 alpha 命中算法。

默认模型在注册表、Electron 与初始渲染路径统一为 Hiyori，避免拉取配置前出现 Haru。窗口隐藏时暂停渲染与配置轮询；监听睡眠恢复事件后重新约束窗口位置。自动化中的睡眠恢复为事件模拟，不是实际让电脑休眠。

最终复测：普通缩放连续运行 300 秒，期间每 30 秒切换 Haru/Hiyori 并隐藏/恢复窗口，每 10 秒记录堆与进程指标，共 30 份采样，渲染错误为 0，JS 堆约 27.9→25.3MiB。该结果只覆盖五分钟，不代表数小时稳定性或整机耗电结论。最终代码另外通过 DPR2 GUI 回归（含模拟睡眠恢复及断屏找回）、3 项几何/资源边界测试和 6 项会话接口测试。真实桌宠已从小窝重新启动，配置为大诗音私聊与 Hiyori；测试回复使用模拟服务，不写入用户真实聊天。
