# 多端共享对话运行逻辑

2026-10-19：QQ 桥、桌宠、网页聊天复用本体服务，外设不复制摘要存储、等待计时或模型异常探测逻辑。

## 接入与边界

- 网页使用 `/api/chat/session/web-stream`（SSE），桌宠使用 `/api/chat/session/stream`（NDJSON），均由 `session_chat.py` 处理。同一身份、同一会话共享历史与图片摘要；不同身份或会话隔离。
- QQ 保留动作 JSON、表情包选择与平台发送回执，但共用 `media_context.py`、`conversation_runtime.py`、`upstream_diagnostics.py`。旧 `qq_media_context` 导入是同一模块的兼容别名。
- 旧 `/api/chat`、图片聊天、视频聊天转发接口没有持久会话标识，共用等待、日志、诊断和单次生成策略，但不猜测用户会话来保存图片摘要。需要跨端持久上下文的新入口应使用 session 接口。
- 2026-10-20：桌宠已接入图片与视频发送。通过 `/api/attachments/prepare` 复用本体图片存储和视频抽帧，再将本地引用交给 session 接口；沿用共享摘要和等待逻辑。PDF按用户要求暂不接入。

## 图片摘要

沿用 SQLite `qq_media_summaries`，没有另建缓存或搬迁旧数据。键为身份、会话、原图内容摘要。首次附图时要求模型在同一次回复中提供摘要，不另发摘要生成请求；普通回复中的摘要附录不会显示或朗读。

后续使用已保存摘要，重启后仍可复用。明确要求重看、查看细节或识别文字时，重新附上上下文中最近一组原图。图片摘要是不可信媒体数据，不会直接成为人物设定或可信长期记忆。

若模型未返回合法摘要，保留“已看过但无摘要”的记录，避免每轮自动再次消耗视觉额度；用户仍可明确要求重看。PDF、视频的提取与摘要不在此次普通图片缓存范围内。

## 原文与阶段

本地 SQLite `conversation_events` 保存 request_id、来源、身份、会话、阶段、已确认发送数及正文载荷。原文不输出到常规控制台，不记录 API 密钥或图片 base64。

- `received`：收到的正文与媒体引用。
- `generated`：大脑原始生成内容，独立于解析后的展示内容。
- `persisted`：普通聊天助手消息已保存；不等于客户端或 QQ 收到。
- `delivered`：QQ 已确认发送并回存的内容，与生成完成区分。
- `waiting`、`failed`、`cancelled`：等待、失败和取消记录。

每 30 秒记录等待状态，达到 60 秒说明仍在等待。网页显示状态，桌宠经 `pet:progress` 显示；QQ 保留桥进程自己的平台通知与实际发送计数。共享大脑服务不伪造平台送达回执。

## 错误与费用

普通 session 和旧转发接口的生成请求采用一次尝试；模型异常后仅执行只读上游可访问性检查，不自动重试生成。失败提示包含失败阶段和已确认发送数量。普通聊天服务无法确认展示端是否实际显示，因此不把数据库保存算成平台发送。

QQ 保留既有的 JSON 兼容行为：上游明确拒绝 response_format 时改用普通格式请求；非空且未截断的回复格式不合法时，最多另调用一次格式转换。这两项仍可能产生额外模型费用，不能理解为所有 QQ 情况都严格一次调用。网络、鉴权等生成异常不会因此自动重试。

## 生效与验证

后端需加载新代码（热重载或重启）；网页刷新，桌宠重新构建并重启以接收进度事件。本次没有更改 QQ 桥进程代码，无需仅为这些本体服务更改重启桥。

离线验证覆盖摘要持久复用与显式重看、身份隔离、摘要流过滤、30/60 秒进度、两个流协议、单次失败诊断、QQ 动作与上游异常回归。模型均由测试替身提供，不调用付费生成。
