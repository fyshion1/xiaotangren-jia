# QQ 桥接排障记录

本文记录 QQ 小糖人桥接曾出现的典型故障、根因和当前处理约定。

## 1. 统一错误掩盖真实原因

旧实现把上游 HTTP 错误、网络超时、内容审核、模型空回复和 JSON 解析失败全部转换为：

> 本轮回复未能形成有效气泡

这样只能知道“没有发出去”，无法判断该改配置、重试接口还是修提示词。现在回复流程按阶段记录安全诊断日志，并返回诊断号：

| 阶段 | 含义 |
| --- | --- |
| `upstream` | 模型接口、网络、密钥、模型名或额度问题 |
| `generation` | 上游审核拦截或生成被拒绝 |
| `parse` | 返回内容不是可用动作 JSON |
| `format_repair` | 普通台词转动作 JSON 也失败 |

日志不记录 API 密钥、完整提示词、图片数据或模型原文。

## 2. 通用聊天格式和 QQ 格式冲突

网页聊天提示词要求角色名加 Markdown 台词；QQ 接口需要严格的动作对象：

```json
{"actions":[{"type":"text","speaker":"角色ID","text":"短句"}]}
```

两套格式同时注入时，模型可能输出普通台词，QQ 端无法发送。QQ 请求会移除冲突的群聊格式，并明确要求动作 JSON。

## 3. 不应只依赖提示词约束 JSON

视觉模型、第三方 OpenAI 兼容中转和不同模型对格式指令的遵守程度不同。当前策略是：

1. 优先使用接口的 `response_format=json_object`。
2. 兼容代码围栏和 JSON 外的说明文字。
3. 若返回普通台词，只做一次独立格式转换。
4. 转换结果再次经过角色、类型、气泡数量和本地附件白名单校验。
5. 转换失败就保留原消息，不发送猜测内容。

不支持 `response_format` 的接口只在明确返回相关 400 时降级；鉴权错误不会盲目重试。

## 4. 角色名称和角色 ID 不一致

动作协议使用角色 ID，例如 `dashiyin`。模型有时会输出显示名“大诗音”，导致动作被静默丢弃。现在允许唯一显示名映射到 ID；未知角色仍会拒绝，避免把话发给错误角色。

## 5. 截断、思考过程和重复 JSON

- `finish_reason=length` 表示 JSON 可能被截断，会单独提示长度问题。
- 完整的 `<think>...</think>` 会在解析前移除。
- 未闭合思考标签、多个动作对象或无法确定的普通文本会拒绝发送。
- 代码围栏可以兼容，但不会把围栏或解释文字发到 QQ。

## 6. 消息保存边界

用户入站消息先保存，便于重试和追查。助手回复只有在 QQ 实际送达后才保存；模型失败、解析失败或格式转换失败不会伪造助手消息。原始用户消息和附件不会因回复失败丢失。

## 7. 现场排查清单

1. 记录诊断号和完整错误详情。
2. 查看 `stage`，先区分接口问题和输出格式问题。
3. `upstream`：检查 QQ 桥模型、视觉模型、API 地址、密钥和额度。
4. `generation`：检查供应商内容审核和模型能力。
5. `parse`：查看 `finish_reason`、角色 ID、`actions`、`type` 和文本长度。
6. `format_repair`：确认模型是否持续输出普通聊天、思考过程或不完整 JSON。
7. 修改配置或代码后重启后端，再发送一条最小文本消息验证。

## 8. 保护性原则

- 不把普通台词、思考过程或未知角色内容直接发送。
- 不因为格式失败而无限重试或重复收费。
- 不在错误信息中泄露密钥、完整聊天记录和图片内容。
- 所有动作在发送前必须通过本地白名单校验。

# 2026-10-22：搜索完成但 QQ 回复格式校验失败

诊断号 `b3d2a9a595`、`29cad4594f` 对应的本地 `conversation_events.generated` 原文显示：搜索已有结果，模型返回带角色署名的 Markdown 台词，但同一角色的后续段落没有重复署名。旧普通台词兼容器逐行要求署名，因此报告「多人普通台词必须明确标注在场角色」。这不是搜索失败或网关发送失败。

修复：只有完整生成结束、尚未发送任何动作时，才本地转换这类台词。第一段必须明确署名；无新署名的续段沿用上一位角色；未知角色、工具/分析标签、损坏 JSON 和截断回复继续拒绝。不调用额外模型做格式转换。失败事件增加诊断号、阶段及原因，可与此前已持久化的生成原文关联。

离线重放上述两轮及更早一轮失败原文均转换为三位原有角色的动作；不会补发历史回复。代码由后端加载，需重载后端后生效，单独重启 QQ 桥不会加载后端代码。
