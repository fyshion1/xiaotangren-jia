# 工具中心与聊天 Agent

通用文字收录现支持独立资料草稿，不必先有目标文档。只需开启「补充知识草案」；用户预览确认后才保存原文并建立检索。操作、路径及限制见 [通用资料收录](knowledge-capture.md)。下文“需三项能力”的流程仅指检索并补充已有文档。

2026-10-22 歌词全文读取：联网搜索授权同时提供 `lyrics_search` 和 `lyrics_read`。搜索结果仍保留短摘录；用户要求读完整首或讨论歌曲时，模型核对候选歌名、艺人和版本后，以候选 ID 调用 `lyrics_read`。每页最多 1200 字，使用 `next_offset` 连续读取到 `complete=true`，避免共用工具的 4000 字上限截断 JSON。尚未读完必须明确说明，不能把开头当整首；QQ 工具助手应将全曲理解、版本和来源传给角色。正文分页同样能在工具执行记录核对，不自动写入知识库。预算和超时仍遵守工具中心设置；本次未调用付费模型或发送真实 QQ 消息。

2026-10-22 复查后续 QQ 搜索记录：当查询把艺人写作 `765millionstars` 时，LRCLIB 的查询字段对格式较严格，结果落到了 Google 摘要，因此那几轮没有执行 `lyrics_read`，实际上没有读到全文。现在会先将数字与字母粘连的艺人名规范化后重查，再以规范化后的完整艺人名本地严格过滤，最后才退到歌名搜索和 Google。提示也明确允许角色讨论全文的主题、情绪和喜欢的段落，不因避免整首照抄而回避正常讨论。

入口：网页聊天输入框上方的「✦ 工具能力」、小窝的「工具中心」，以及桌宠聊天框内的「✦ 工具中心」。也可以打开前端地址 `/#tool-center`。

工具默认关闭。在工具中心选择允许使用的用户人格、网页/桌宠渠道、允许目录和能力，开启后点「保存工具设置」，下一轮生效。仅支持有记忆的普通文本聊天与桌宠文本聊天；语音及测试聊天沿用原流程。配置属于本地应用设置，用户人格限制不是多用户认证。

目前提供查看目录、读取 UTF-8 文本、按文件名寻找文件、确认允许目录及限制、联网搜索等能力。联网搜索同时支持通用网页查询和歌词专用查询：歌词先按歌名/艺人从 LRCLIB 找精确元数据候选，只给模型最多 80 字开头摘录及来源；没有精确候选时才用 Google 网页摘要兜底，不把视频搜索结果当歌词。歌词搜索随「联网搜索」授权，不单独开放 B 站等视频来源。另有独立勾选的「提醒草稿」能力，用户在工具中心确认后才生效，见 [提醒使用说明](reminders.md)。每项卡片都提供示例；从聊天打开时可直接填入输入框，从小窝打开时可复制。默认目录为数据目录下的 `tool-sandbox`，可放入自己的测试文本；工具不会写入文件内容。

调用过程会显示开始、成功或失败。网页可展开当轮结果；桌宠显示简洁状态。工具中心可以查看最近 20 次运行记录。联网及歌词搜索会保留搜索词和最多 4000 字初始结果，方便核对模型实际读到的摘要；本地文件、个人记录等隐私结果不写入运行历史。歌词结果只保存短摘录与来源，不自动收录整首歌词。模型最终回复属于聊天内容，若引用文件内容，仍会按普通聊天消息保存。

用户明确要求把查到的资料补进个人知识库时，只有在「查个人知识资料」「展开笔记出处」「补充知识草案」三项能力均已开启的情况下，Agent 才能查找目标文档并创建带来源的待确认草案；用户仍需在个人数据库知识资料区确认，才会写入正式文档。工具未授权时，Agent 应提供可复制的来源摘要，不得声称已经入库。此流程针对主人的个人知识库，不会写入角色沙盒记忆。

点击「停止本轮」取消客户端请求并停止等待，保留用户消息。同步文件处理使用线程，取消或超时不能强制终止已开始的线程操作。切换网页会话也会取消当前请求。

## 执行路径

QQ 普通对话先经过共享的本地 BGE 意图门控：明确闲聊跳过工具助手模型，工具请求与不确定输入进入原工具流程，规则不再只依赖桥客户端的关键词。权限检查仍先执行；说明与独立检测命令见 [本地意图路由](local-intent-router.md)。网页、桌宠尚未接入这一门控。

React/桌宠 → 现有会话接口 → 本体可信沙箱适配器 → Python `AgentRunner` → 模型 `tool_calls` → `ToolExecutor` → 结构化工具结果回填 → 最终回复。网页使用 SSE，桌宠使用 NDJSON。默认最多 6 轮、8 次调用，单轮最多 3 次，整体 60 秒；可在界面调整部分预算。参数错误仅允许一次纠错；相同工具及规范化参数的重复调用会停止，防止死循环。底层只读工具仅对显式声明的临时错误有限重试。

工具开启的聊天采用非流式模型决策，在执行期间发送进度，最后显示回复；未开启工具时保留原有逐字流式聊天。模型供应商需要支持 OpenAI 兼容的 `tools/tool_calls` 协议。网页与桌宠共用此循环；QQ 桥共用执行器，目前保留原循环。外部适配器的 `/api/nest/tool-turn` 仍只负责转发模型决定。

通用网页搜索、歌词搜索、个人知识资料检索及草案、项目费用和日常饮食记录已接入共用工具循环。QQ 桥复用工具执行器并保留独立配置。一次性提醒已接通网页/桌宠；QQ 尚未接提醒，仍使用既有工具循环。
