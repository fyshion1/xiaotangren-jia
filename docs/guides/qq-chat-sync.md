# 默认篇幅与 QQ 双向同步

网页聊天保持每位实际发言角色约 250～400 个中文字的中短描写。QQ 单独使用即时聊天策略：日常分享时每位实际发言角色通常一两句、约 10～60 字，按完整语意和说话节奏分气泡；复杂问题、认真倾诉或要求展开时充分回应。篇幅是参考，不设硬截断。QQ 提示中移除公共网页篇幅块，防止两套长度要求冲突；角色卡、称呼、既有关系和边界继续生效。

QQ 的亲近感来自接住分享欲、具体回应、角色自己的念头与自然接话；允许按人设撒娇或打趣，不强制轮流发言、不复制同一种感叹，不虚构共同经历或用固定昵称制造亲密。动作神态按情境简短出现，用户示例不作为固定台词。图片摘要仍在内部元数据中返回，不占角色气泡。

网页默认输出预算为 6000 tokens，旧版 800 默认值只迁移一次，用户其他自定义预算保留。QQ 输出预算仍按出场人数分配，最低 4096、最高 12000 tokens（含视觉摘要预算）；预算是上限，不是要求写满。

QQ 原消息与实际送达的回复仍写入共享聊天记录。网页保存的用户消息、完整角色回复、图片和视频引用进入 SQLite 持久化队列；每个账号、每个身份会话只关联一个 QQ 目的地，采用最近收到合规 QQ 消息的对应会话。启动时，白名单中只有一个明确对应目的地时可自动关联；存在歧义时先在目标 QQ 会话发一条消息完成关联。换目的地不补发旧目的地的积压，也不会广播到所有白名单。首次启用不回放历史。

设置中的「网页消息同步到 QQ」（`sync.to_qq`）默认开启；关闭会暂停发送。桥每 2 秒检查一次，并沿用发消息间隔、白名单、账号人格、用户身份和静音设置。网页用户文字标为「【网页用户】」，角色回复保留角色署名。图片与视频原附件可以传到 QQ；模型依然只看受预算限制的图片与本地视频抽帧，不会收到原视频。同步不调用模型、不另存一份助手回复。

队列在网页消息入库时注册，QQ 来源记录不进入队列。发送成功后先保存本地回执，再确认后端游标；后端回执失败只补确认，不重发 QQ 消息。消息删除后自动跳过。QQ 网关没有幂等发送键，因此网关已送出却未返回、或送达与本地回执落盘之间进程被强制终止的极端窗口，仍可能重复，不能承诺严格 exactly-once。

更新后网页需刷新；后端若未启用 reload，需要重启。QQ 桥是独立进程，始终需要单独重启以加载代码。

## 收发原文与未完成状态

### 首气泡提前发送

#### DeepSeek JSON Output 维护约束

依据用户提供的 DeepSeek 官方文档摘录（2026-10-20；[官方 JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode)），后续调整模型请求与提示词时保留以下条件：

- 请求设置 `response_format: {"type":"json_object"}`。
- system 或 user 提示中必须出现 `json` 字样，并提供期望的 JSON 格式样例。当前 QQ 提示包含 `JSON` 和 `actions` 对象样例。
- 合理设置 `max_tokens`，避免 JSON 被截断；当前 QQ 预算为 4096～12000，截断回复不能当作完整成功。
- JSON Output 仍可能返回空 `content`，官方建议尝试调整提示词缓解。空正文必须保留错误诊断，不能视作有效回复，也不据此断定是网络故障；本项目不因此自动重试付费生成。

合法 JSON 不保证符合本项目动作结构，也不保证角色 ID、表情候选或动作顺序正确，现有业务校验与流式动作解析仍需保留。以上约束同样适用于使用该功能的流式请求；兼容中转是否实际支持需单独验证。

#### 流式发送与兼容处理

2026-10-20 01:16 实际返回格式补充：兼容在场角色的 `**角色名**：台词` 署名，以及紧邻合法署名前的字面量 `\n` 分隔。只去除署名的粗体标记，不改写台词；未知角色仍拒绝。该轮已保存的原文离线回放可还原三条动作，未调用模型、未补发旧消息；真实 QQ 送达需另行验收。解析失败的 QQ 系统提示明确指出格式校验问题，不再一律引导检查上游可访问性。

流式请求携带 `response_format: {"type":"json_object"}`，不额外重试生成。若渠道仍返回普通台词，仅在正常结束、尚未发送任何动作时做本地转换：单角色可省略署名，多角色每行必须使用在场角色的唯一名称或 ID 加冒号。结构残片、思考标签、代码、未知署名与截断输出拒绝转换。带代码围栏等可恢复的完整动作 JSON 也在结束后校验发送；这些兼容路径需要等完整正文，不保证首气泡提前。兼容转换记入 `QQ local dialogue compatibility` 日志。此修正已加入离线回归，实际渠道与 QQ 送达仍需现场验收。

普通 QQ 回复使用本机 NDJSON 流式端点 `/api/qq-bridge/reply-stream`。模型直接返回以 `actions` 数组开头的 JSON；只解析数组内已闭合的完整动作对象，校验角色、文字长度、表情候选、气泡数量和身份后，立即交给网关发送。图片摘要在动作列表后生成，仍在完整成功结束后保存。半句、半截 JSON、思考内容和摘要不作为气泡发送。网页聊天格式和篇幅不受影响。

每个气泡继续沿用发送资格租约、白名单/静音/会话检查和持久送达回执。模型后续中断、格式错误或审核终止时，已确认发送的气泡不会撤回或重发，系统提示说明部分完成；用户续发时保留已发部分，停止旧尾句。不能在提前发送时预知上游最终审核结果。最终完整 JSON 仍校验，和已输出动作不一致时整轮标为未完成，不补发可疑尾句。

本机流每15秒发送保活，普通等待提醒仍生效；不支持流式的模型渠道会明确报错，不自动回退到非流式另开付费请求。旧非流式端点保留给旧版客户端；更新后需重新启动 QQ 桥，后端未开启 reload 时也要重启。沙盒通知和主动联系继续使用各自受预算限制的既有通道。

前端「QQ 桥」现有运行日志会保留：收到的用户原文、附件入库后的正文与本地引用、大脑生成的待发送气泡，以及 QQ 网关确认发送的逐条正文、角色与平台消息编号。带目标会话、来源消息编号和北京时间。正文采用 JSON 字符串保留，换行转义，避免用户文字伪装成运行日志；不记录模型密钥、请求鉴权头或图片 base64。日志沿用本体运行器的本地追加文件，桥重启不会清空；不是只保留内存中的消息计数。

“大脑返回”只表示生成完成；只有“QQ 已确认发送”才是网关确认成功。送达后写后端记录失败，只补回执，不重新发送。新输入、静音或身份/阵容切换使旧计划停止时也会说明原因。网关确认不等于对方已读。

等待模型或本地工具期间，每 30 秒记录进度，超过 60 秒在 QQ 提示仍未收到完整回复；排队也会明确提示。提示按目标用户及类型每 60 秒限一次，白名单与静音限制继续生效。后端一轮回复总等待 360 秒，桥最多等 375 秒后放弃本轮等待；底层 HTTP 线程由自身超时收尾，不把迟到结果当作新回复发送。已有旧版桥的请求超时仍保留为 390 秒，防止抢先截断后端诊断。

失败记录处理阶段与已送达数量，并尝试在 QQ 发送独立系统提示。系统提示不冒充角色发言，不记入助手聊天或长期记忆；纯失败轮次不启动额外的模型记忆提炼。QQ 网关本身无法发送时，提示也可能发不出，但前端运行日志会明确记录。不会自动重试付费生成请求。主动静音、白名单拒绝和正常的旧计划停止不视作上游故障。

模型调用异常时，优先保留真实错误分类及诊断号，再以同一上游配置只读请求 `/models`（最多约 5 秒的网络超时）补充入口、HTTP 状态和模型是否仍列出。检查不调用生成接口、不传聊天内容；清单可达不代表具体模型通道健康，清单不列出也不能单凭此认定模型下线。接口不支持标准清单时明确报告状态未知，不循环探测，不自动换模型。可以据此优先检查服务商状态、模型名称和权限，同时保留本地/网关失败的独立分类。
