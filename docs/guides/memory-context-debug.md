# 记忆与图片上下文排查（2026-10-19）

聊天页「记忆」只打开短期上下文面板；长期记忆在私人空间管理，参见 [完整流程](memory-workflow.md)。

- **短期记忆池**：显示当前已载入历史按「历史注入条数」裁剪后的文字与图片。图片在窗口内会随追问继续发送，并使用视觉模型；超出窗口后不再携带。
- **最近一次实际发送记录**：由后端在调用 provider 前通过 SSE `context` 事件回传，显示实际模型、system、消息文字和每条消息的图片数量。它只保留页面打开后的最近一次请求，不持久化，也不代表上游已成功识图。失败请求也可能留下此记录。事件不包含密钥或图片字节。
- **核对上游多模态消息**：只组装、不调用模型，可以查看图片转换后的 `image_url` 内容与预览。这里是当前预览，上一轮以「实际发送记录」为准。
- **当前身份的长期记忆注入开关**：在私人空间记忆中心管理；只使用批准且满足权限的资料。

修复的原因：旧 `buildOutbound` 只发送文字；看图接口不携带历史；身份挑选只排除关闭条目，却继续召回未挑选条目；记忆按钮跳转身份挑选页后，原管理浮层失去了入口。

现在普通聊天、看图和视频抽帧共用消息组装器。本地图片引用在服务端转换成 data URL，避免上游无法访问本机 `/api/files/...`。历史图片文件失效会明确报错，防止静默丢图。

存在身份时只注入该身份挑中并开启的长期记忆；没有身份的调用不注入个人长期资料。小窝和 QQ 桥采用同一规则。

验证路径：上传一张有明显文字或物体的图片 → 查看实际发送记录中图片为 1 → 下一轮询问具体内容 → 再核对该轮历史消息中图片仍为 1。将一条长期记忆取消挑选或关闭后，确认实际发送记录的 system 不含该条。真实识图效果仍需使用已配置的视觉模型验证。
