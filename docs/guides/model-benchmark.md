# 上游模型测速

从仓库的 `backend` 目录运行，使用现有 Python 环境：

```powershell
.venv/Scripts/python.exe -X utf8 ../tools/model_benchmark.py --feature qq_bridge --mode both --output data/diagnostics/model-benchmark.json
```

这是独立命令行工具，不需要启动 QQ 或本体 HTTP 服务。可导入的执行模块为 `app.services.model_benchmark.probe`，只依赖 httpx，不依赖数据库。`--feature` 是可选的本体现有配置适配器；不修改任何配置，也不切换正在使用的模型。

独立环境可通过 `--base-url`、重复的 `--model` 参数及 `MODEL_API_KEY` 环境变量提供配置。密钥不放命令行参数或报告中。最多比较三个模型，默认流式一次，`--mode both` 每模型请求两次，无自动重试。只发送固定三句短文本，不读取或发送聊天历史、人设、记忆和图片；生成可能计费。`--timeout` 为每次请求总时限，默认45秒、最高120秒；`--max-tokens` 默认为512，允许32～1024，思考模型可能把预算全花在内部推理上。

报告字段包括响应头等待、流式首次可见正文、总时长、正文字符数、终止原因、上游报告的输入/输出/思考 tokens。非流式无法测首字延迟，字段为空；吞吐量按输出 tokens 除以总耗时计算，包含排队和思考，不能当作纯正文解码速度。响应正文及思考内容不写报告。错误只记录状态码或异常类别。缺失用量不自行估算；上游报告用量超过请求预算会标记 `reported_budget_exceeded`，客户端无法替不遵守预算的供应商保证账单上限。

单次样本只用于发现明显问题，不能认定模型长期速度或角色表现。流式接口不兼容 `stream_options.include_usage` 时会明确失败，不自动另开付费请求。模型清单可达不代表生成通道健康；日常失败诊断仍由公共 `upstream_diagnostics` 的只读检查处理。

QQ 额外记录 `timings`：上下文组装、上游等待、后处理及后端总耗时。桥日志区分上游前处理（工具和回执）及大脑请求往返。普通闲聊在工具开启时也跳过工具模型，提到文件、目录、搜索、本地操作等再进入工具阶段；工具权限和沙箱校验仍在执行入口。不使用自动换模型或故障后自动重试。

QQ 普通回复现已接入 `/api/qq-bridge/reply-stream`：模型流式返回动作 JSON，完整气泡校验后即可发送，不等待后面的气泡或图片摘要。桥日志分别记录首个模型文本与首个气泡实际送达时间。原有非流式端点保留供旧客户端使用，流式失败不自动回退或重试生成。
