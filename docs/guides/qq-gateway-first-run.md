# QQ 桥首次接入与连接诊断

非专家模式使用单账号简化面板，日常保留角色、聊天范围、语音和表情；技术参数放入「连接修复」。范围与模式切换规则见 [QQ 桥简化模式](qq-basic-mode.md)。

GitHub 仓库只包含桥，不包含 SnowLuma 和 QQ。三者缺一不可：兼容版本的本机 QQ → SnowLuma 网关 → 糖人 QQ 桥。

1. 打开小窝的 QQ 桥面板，点击「检查安装与 QQ」。找不到网关时，先检查安装目录；默认的 `D:\SnowLuma` 只是历史配置，不要求必须有 D 盘。
2. 未安装可点「查看官方版本并准备安装」，核对发行说明与 QQ 兼容版本，勾选同意，再点确认安装。当前自动安装支持 Windows x64，只从 SnowLuma 官方 GitHub Releases 下载完整 ZIP，安装到 `backend/data/gateways/SnowLuma` 并更新网关目录。不覆盖已有目录，不自动执行、登录或接受协议。网络限流时可按官方发行说明手动解压，再填写目录。
3. 使用所选 SnowLuma 发行说明支持的 QQ 版本，启动并登录机器人账号。检测到低于 9.9.33 的 QQ 会提示较旧，但这不是对 9.9.33 及以上版本的兼容保证；构建号和网关版本也需匹配。版本读取不到时显示未知，请自行在 QQ 设置核对，不假报“版本太低”。
4. 点击「开 QQ 网关」，访问设置中的网关网页地址（默认 `http://127.0.0.1:5099`）。首次密码来自网关启动日志，不写死为通用密码；面板可主动展开启动日志中的初始密码提示。若网关是手动启动的，查看其启动窗口。完成网关协议与隐私确认、修改密码、加载机器人 QQ，确认 OneBot 正向 WebSocket 服务已启用。
5. 将修改后的网页密码保存到小窝下方「接入方式 → 网关网页密码」。网页密码不是 OneBot access token。在账号列表「选 QQ」，使用现有自动配置流程读取所选账号的 WS 地址、token，分配不冲突端口并读取好友/群名单，再保存。无需用户自己推算端口；多账号各有连接，不能共用同一个号的 WS。名单读取失败会明确提示，连接信息可保留后重试。

## 一直 connecting 时

- 找不到完整运行文件：尚未安装，或安装目录填写错。先解决这一项。
- 网关网页也打不开：网关未启动、启动失败或网页端口配置不对。查看网关启动窗口。
- 网页正常，但没有账号加载：确认 QQ 已登录、版本及构建号匹配，查看网关加载错误。升级 QQ 后需重启 QQ 与网关。
- 账号正常，但 OneBot 端口未监听：在网关启用正向 WS，检查端口冲突，然后重新「选 QQ」读取配置。
- WS 返回 401：检查账号、token 和所连服务，不通过反复换端口碰运气。

安装与密码查看只开放给本机前端后台，不作为模型或沙盒工具。安装预览与确认绑定发行版本；发行版变化要重新预览。密码提示不进入轮询诊断，不打印到工具记录。

官方来源：[SnowLuma README](https://github.com/SnowLuma/SnowLuma#快速开始)、[发行包及兼容说明](https://github.com/SnowLuma/SnowLuma/releases)。上游更新可能改变安装要求，请优先核对所选发行版说明。
