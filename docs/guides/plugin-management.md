## 管理入口

进入设置区域的 **插件管理**，或打开网页 `/#plugins`。入口属于本体，不依赖主题或专家模式，关闭主题后仍可进入。

- **隐藏入口**：从“一起玩”功能列表收起，不停用插件。管理页仍可显示回来。
- **关闭插件**：先暂存选择，点击“应用修改”才保存停用状态，停止本体登记的运行进程，拒绝再次启动与已挂载的对应插件接口。工具、主题、酒馆和自主活动加载器也检查此状态。不替代操作系统进程管理，不承诺关闭用户在本体之外手动运行的独立程序。
- **卸载插件**：先关闭，再把独立目录移至 `backend/data/uninstalled-plugins/<目录名>`。备份存在时拒绝覆盖；不会永久删除文件、配置、聊天或记忆。用户可点击恢复，恢复后保持关闭，再手动启用。

状态存于本机 `backend/data/plugin-state.json`，不进入 Git。操作只允许从本机管理页面发起。卸载会移动独立仓库目录，正在用编辑器或其他程序占用时可能失败；失败会显示错误，插件保持关闭，可重试。网关或外部浏览器不随插件卸载删除。

## 关闭主题查看效果

在“小糖人主题与设定”卡片点 **关闭插件**，再点 **应用修改**。Vite 在应用后监听到主题/酒馆模块开关变化才重启，页面重载后使用中性界面；可在同一卡片点 **启用插件** 并再次应用恢复。仅隐藏入口或切换不影响编译模块的插件不会触发此重载。

开关和隐藏操作可连续调整，统一通过 `POST /api/plugins/apply` 应用；服务端先检查整个批次及状态冲突，成功停止所需进程后只写一次状态文件。“放弃修改”恢复当前已应用状态。离开管理页未应用的草稿不保存，关闭/刷新网页时有待应用修改会触发浏览器提示。卸载、恢复仍是独立即时操作，有待应用修改时暂不可用；原单插件管理 API 保留兼容。

批次停进程不具备操作系统级事务：若后续插件停止失败，状态文件不写入，但先前已经停止的进程不会自动重启，应检查错误并重试。

## 本体外观入口

顶栏“外观”属于本体，关闭主题也保留。默认只提供石墨灰、经典蓝、森林绿、暖米色四种预设，不开放任意 CSS/布局编辑；日夜模式独立保留。偏好存在当前浏览器的 `xtr.core.palette`，刷新保留，不跨设备同步。配色覆盖层在可选主题样式之后加载，选择预设无需重载页面；复杂装饰仍归主题插件。

这是主题模块切换，不只是隐藏装饰：前端改用本体的主题占位实现，不再注入主题页头、样式或静态图片；后端默认提示词随停用状态回退。已有角色档案、上传图片、世界书、聊天和记忆继续保留，已保存的角色专属人设不会被清除。因此现有数据库仍可能显示以前保存的角色名字，已有图片在启动或停用前转存到本体用户资源层，停用后继续提供；源素材缺失时管理操作会提示处理；这与全新空库的中性默认档案不同。

生产构建已将前端模块编译为静态文件，按钮不能改写已发布的 JS/CSS：更改主题或酒馆后，需重新执行前端 `npm run build` 并部署构建产物。后端启动时未挂载的插件路由，重新启用后也需重启后端。已有请求或正在生成的回复可能先完成，不会撤回已输出内容。
