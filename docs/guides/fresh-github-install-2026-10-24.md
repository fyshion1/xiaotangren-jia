# 从 GitHub 开始的首次部署验收

日期：2026-10-24。目标是验证真实新用户依赖环境，不复用维护者的虚拟环境、node_modules、模型、密钥或个人数据。

## 找回的现有流程

根目录 `install-features.py` 是已有可选安装器，`start.bat` / `backend/app/launcher.py` 是已有 Windows 总启动器。详细组件说明在 [optional-components.md](optional-components.md)，主安装步骤继续沿用根 README，不另外维护一套冲突的安装程序。

安装器依次提供桌宠、QQ 桥、联网搜索、QQ 语音转写、本地说话与听写、语义检索，全部默认不安装。其他功能不增加逐项询问，按仓库文档另行安装。

## 本轮发现与修正

1. `pyproject.toml` 之前将 Edge 和 Piper 放在基础依赖，选装说明与实际安装不一致。现将 Edge 放入 `online-voice`，Piper 放入 `local-voice`；基础安装不含语音合成运行库。
2. 先运行安装器、再执行普通 `uv sync` 会移除本次命令未声明的可选依赖。README 基础安装/更新改用 `--inexact`，手动 `uv run` 启动加 `--no-sync`。不要在正在运行的日常环境里用精确同步模拟新用户。
3. 聊天页、手机设置、状态栏、回复朗读、音色与按住说话原先缺少安装状态约束。新增只读 `/api/components` 检测，未安装时隐藏相关入口；检测失败默认隐藏，不启动识别或探测远端服务。
4. Piper 就绪检查需要运行库和非空模型、配置文件；语音引擎不再一律声称可用。只有本地识别时不显示朗读；默认 Edge 不可用时改选可用引擎。缺组件调用朗读返回可操作的 409 提示。
5. 视频通话尚未实现，删除占位入口。按住说话仍是浏览器 Web Speech，不能宣传为本地 Paraformer，提示可能使用浏览器在线识别服务。
6. GitHub 跟踪了 `features/dont-starve-together/README.md`，原先仅按目录存在就显示已安装。功能列表与插件列表现检查代码或安装清单，空目录和纯说明目录不计入。
7. 选择联网时，安装器会先下载缺少的独立 tools 插件，再安装 OmniReach；已有不完整目录不会覆盖。私有仓库仍需要相应访问权限。
8. 启动器增加 `--backend-port`、`--frontend-port`，Vite 代理跟随该实例后端端口，方便新副本与日常实例并行验收；不复用其他目录的服务。

这些修改是可选依赖与入口治理，不表示语音实现已完整迁出为独立插件，也不表示公共插件市场已经完成。

## 从零验收方式

1. 在新的空目录 clone；记录实际 Git 提交。不要复制现有 `.venv`、node_modules、backend/data、`.env`、私人目录、模型和插件。
2. 根目录运行 `python install-features.py`，先完整测试全部回车跳过的文字聊天基线。
3. `backend/` 执行 `uv sync --locked --inexact --python 3.11`；从 `.env.example` 创建新 `.env`，使用自己的模型配置。
4. `frontend/` 执行 `npm ci`，再执行 `npm run build` 验证类型及生产构建。
5. 根目录执行 `start.bat`。需要与日常实例并行时，用 `start.bat --backend-port 18002 --frontend-port 15174`，访问对应前端端口。
6. 新浏览器上下文确认暖米色、角色/身份管理、模型设置、原生记忆、空插件列表和手机布局；语音及未安装功能不应出现。实际模型聊天与检索另行配置并人工验收。
7. 后续单独测试用户实际选择的组件。依赖已安装不等于模型、账号和服务都已就绪。更新和卸载不得静默覆盖或删除用户数据。
