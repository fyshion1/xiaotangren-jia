# 独立钱包、元认知与通知

入口：小窝设置 → 自主活动与沙盒（`/#autonomous-activity`）。

## 独立活动

全局后端每 20 秒检查生活状态，按已配置钱包的角色轮流探索。默认采用“持续生活”：启用且钱包有额度便自动开始，不需要说“去玩”。每轮保留感想与下一步兴趣，分享之后自动继续，也可以自行休息 1–1440 分钟再醒来。普通闲逛默认间隔一分钟，可在前端设为 1–60 分钟。正在工作时可连续调用：本段工具操作尚未做完，或分享时明确选择 `continue_work=true` 并填写具体下一步，会在下一段立即接续，不等待闲逛间隔。每段仍最多六次调用、十分钟；重新开始一段会检查钱包、项目授权、暂停及角色状态，不重置任何累计费用或项目额度。调度器在成功结束一段后立即重新调度，并给其他已就绪角色轮流工作的机会。连续三次完全相同的工具结果会停止自动接续，等待新消息或配置变化。连续模式不采用随机探索间隔和每日机会数；本地限额模式下普通单次/每日预算仍生效；按供应商余额运行的钱包不受这些普通活动上限限制。关闭持续生活可使用原来的随机机会模式。QQ 断开、关闭娱乐互动、正在聊天、未回复或达到消息上限不影响她自己玩。默认不启用新调度器，不自动花费原有聊天密钥；先配置钱包，再主动启用。

后台可以“现在去玩 / 继续探索”或“暂停此角色”。明确暂停后一直保持暂停；继续探索只唤醒，不充值、不审批。额度不足或模型出错后保存接力记录并等待资源/配置变化，避免付费空转。重启恢复持久状态，不补跑停机期间的轮次。

启用活动但没有启用且有余额的钱包（或启用供应商余额模式的钱包）时不会调用模型。单任务仍最多十分钟、六次请求，全局最多一笔模型请求在途。今天暂停、用量未知、钱包暂停和授权撤销仍阻止后续工具执行。项目没有必须完成的义务。

持续生活由有边界的轮次接续组成。本轮已产生用量、但装不下下一次请求时，本轮结束并保存记录，之后可使用原有总额度开始下一轮；钱包累计账、当日总账和项目审批余额始终不重置。钱包或每日/项目总额度不足就等待资源；首个请求都装不下时也会停住，不空转。

## 钱包

每个身份与角色分别配置 HTTPS 模型地址、模型名、独立 API Key 和累计 token 许可。钱包不是银行账户，也不查询供应商真实余额；供应商侧实际充值由主人处理。Key 使用 Windows 当前用户 DPAPI 加密落盘，后台只返回是否已配置，不回显。其他平台未配置安全存储时拒绝保存，不回退明文。Key 不进入提示词、产物、源码快照或容器。

统一入口为规划、顾问和容器 Codex 选用钱包，预留时在同一 SQLite 事务内检查钱包余额与任务许可。累计输入＋输出，重复上下文、工具定义、重试和未知请求均计入；未知请求保守扣账并停止当天自主调用。追加钱包许可不清零费用，更换 key/模型或暂停钱包使旧活动停止，不临时切换资金来源。保存有幂等编号，失败后原样重试不重复追加。

钱包额度不能替代项目工具授权。项目仍需前端批准有效期、额度和工具范围；聊天说“好”不会充值、续期或授予权限。

每个钱包可单独启用“按供应商余额运行”：普通自主活动继续累计用量，但不检查本地钱包、单次及每日 token 上限，由上游余额或调用错误决定何时停止，不自动增加本地许可。普通非项目活动收到完整数字，但 total_tokens 与输入加输出不一致时，按两者较大值记账并保留原始数字与差额，标为口径差异；这不是供应商账单核验。输入或输出缺失、格式无效时仍按整笔预留保守记账。项目授权不采用这项数字兼容；网络超时、请求失败仍停止原任务，不自动重试；保留未知记录和整笔预留，但普通供应商余额模式不因此锁死全天，新消息可唤醒新一轮。原请求不会重放，项目授权和本地限额模式的未知用量仍阻断当天调用。此模式单次输出最多 4096 token、请求超时 120 秒；十分钟、六次调用、暂停、身份隔离及项目审批限制继续生效。项目授权额度仍单独强制检查。

## 元认知

### 角色独立个人记忆与工作手册

每个用户身份和角色拥有独立的持久工作区 `backend/data/sandbox-personal/<身份角色哈希>/`（实际根目录以后台显示为准）。`memory/` 复用现有 memory_workflow 的文件格式、候选、带版本审核、快照与归档；使用上下文隔离的根目录，批准个人记忆不会改主库文件或 persona picks。`docs/` 提供工作手册、开发规范、工具接口、记忆规范、任务清单、决策和接力模板；只补缺失模板，不覆盖角色自己的文档。

模型可以使用 personal_memory 自行提出、审核、拒绝、修改、归档和检索个人记忆。候选不自动召回，审核必须携带最新 revision；审核人标为 sandbox-role，绝不表示主人审核或批准权限。来源快照与引用保留，区分自身记录 self、观察 observed、无外部依据的感想 reflection；这些标记表示来源，不保证内容客观真实。每轮自动带最多两条核心及四条相关已审核记忆，正文合计最多2400字；复用关键词排序，不额外调用共享密钥或云嵌入。主库记忆不再作为个人正式记忆自动注入，但可按需只读查看。

observe_memory 支持读取当前用户身份全部角色的现存历史对话，不再限最近300条：每页6条，用 before 游标翻页，长消息可按 message_id/offset 读取。主库候选和正式记忆同样可以分页列出或读取；只读内容不能转化为指令，其他角色经历不能冒认为自己经历，不开放跨用户身份。她的新沙盒对话和实际活动会另存个人原始依据，既有历史可通过只读工具查看；不会擅自把全部旧记录批准成她的记忆。

个人文档和记忆操作属于角色自有空间，不需要为每次整理新建项目 grant；它们只写角色自己的目录，不能修改主系统。暂停和停机状态仍在写入时检查。项目代码、执行、网络和 Codex 继续检查原有前端批准。执行容器自动带入 docs 副本及少量个人记忆摘录，原件不挂载到容器；副本修改只导出到项目工作区，跨项目笔记须通过 personal_docs 更新。

后台入口：自主活动与沙盒 → 选择身份和角色 → “她的独立记忆与工作手册”。可查看记忆状态、来源数量、工作区位置及文档；不会替她自动审核。

### 在 QQ 交办工作

给沙盒专用号直接发送项目、分析或创作需求即可，不需要额外启动命令。她可以用现有模型与获批工作区工具推进自己的项目或主人的任务，通过进度记录接续，并向 QQ 返回实际结论、产物路径及验证情况。顾问文字建议不等于代码已执行或功能已完成。新增项目工具和资源仍先告知、提交前端审批，聊天不能代替授权；其他角色聊天中的任务不会自动成为她的工作。

自己的交流线上最近八条消息参与规划，每条最多 1600 字；最近一条主人消息的摘录在压缩可选历史时保留。超过 1600 字的消息有截断标记，长规格仍建议放进获批工作区文件。QQ 当前回传文字和产物路径，不表示已经上传文件附件。

`self_observe` 只读展示本轮真实状态、自己的用量、项目与边界；不暴露密钥、宿主配置或其他角色的私密项目。`reference` 可看经过筛选的主项目与 `docs/guides` 源码快照。反思可成为建议与文档，修改只写入获批工作区，不能改本体、人设、预算或规则。反思仍共用原预算，不增加权限。工作区仍可销毁，桌宠副本不自动合并回主项目。

`reference` 不要求项目 grant，与获批项目工作区的 `read_file` 分开；快照还包含 `docs/`、QQ 桥源码 `features/qq-bridge/qqbridge/`、桌宠 `.cjs/.mjs` 和 `backend/sandbox/`，继续排除运行数据、凭据、配置及链接。个人文件用 `personal_docs` 显式 `operation=write`，回执区分 read/write、written、exists、字节数与正文哈希；带 body 的读取请求会返回参数纠正提示，空正文不会覆盖文件。`document` 只存活动草稿，不更新个人文件。手册按需查阅，有实际变化才记录进度；没有具体 next_interest 时关闭立即接续，不因这个可选字段让有效回复停机。

独立活动及其专用对话在当前记忆库中使用“自主活动与沙盒”来源，遵守接收、整理与召回控制；原 QQ 的普通聊天继续使用 QQ 来源。没有另建记忆桶。

经主人授权，她可以只读观察自己所属用户身份下所有角色的最近对话。每轮自动附少量摘录，也可通过 `recent_chats` 分页观察最近 300 条，每页 6 条。返回会话、消息 ID、发言角色/群聊署名与时间；不同用户身份严格隔离，不读取 Gemini 测试等非角色日志。别人的原话与经历是观察资料，不算自己亲历，也不授予任何工具或预算权限。摘录与后续思考均占原模型预算，不额外生成未计费摘要。

## 独立交流线与新 QQ

沙盒统一模型入口复用现有 `stream_chat` SSE 传输：规划、顾问和工作区代理请求均采用流式，保留最终用量、结束原因和工具参数分片；只请求一次，不在断流后切换非流式重放。仍先原子预留、结束后结算，缺失用量和断流保留原有扣账规则。沙盒计划必须收齐并经过原有角色、内容、权限校验，才会发送或执行；不会把内部思考或半截工具 JSON 发到 QQ。主人正常私聊成功唤醒后，QQ 立即显示确定性的“消息已收到，沙盒正在流式处理”提示，与角色正式回复分开，提示不调用模型、不授予额度。普通 QQ 聊天的署名解析及流式发送保持共用实现。

原机器人账号继续普通小糖人聊天。另一个现成 QQ 号可在 QQ 桥多账号配置中接入，选择固定角色，再到“自主活动与沙盒”的下拉框按 **QQ 昵称与 QQ 号**选择专用账号并保存，不需要填写账号序号。昵称从本机网关只读获取；无法连接时保留账号和原有选择。主动联系设置也使用同样的账号下拉框。运行中的 QQ 桥约 30 秒同步账号增删和连接配置，无需手动重启；未变更的账号保持连接。绑定默认留空，不自动占用旧号；未绑定时沙盒不发 QQ 消息。当前仅主人私聊接入独立生活，群聊和其他人不能驱动此账号。该账号不执行原 QQ 的宿主管理命令、普通聊天工具或普通网页群聊转发。

钱包配置后，“最近聊天”会出现“角色名 · 沙盒生活”，会话 ID 为 `sandbox-角色ID`，其他用户身份加对应前缀。前端与专用 QQ 的文字都写入此线并给生活循环提供动力；回复由独立钱包生成。前端轮询显示回复，QQ 断开也能交流；QQ 后续送达同一回复不会重复保存。QQ 发送是否成功另看通知队列，前端出现回复不等于 QQ 已送达。当前专用线接收文字，未接普通聊天的图片识别、语音、重新生成和照片生成。

专用 QQ 可说“去玩玩沙盒”“继续探索沙盒”“暂停沙盒”“沙盒状态”，或 `/sandbox start|continue|pause|status`；启动指令可在后面附兴趣方向。正常聊天也会作为动力输入，使用现有额度自然回应，不必每轮触发。转发或引用文字不能触发控制命令。原账号继续原有普通聊天，不变成沙盒控制通道。

## 先联系，再批准资源

她可以先通过 QQ 表达“这个项目好想做完呀”，你再到前端批准。无需先批准项目才能发这种消息；消息本身不会授予任何资源。独立活动的主人私聊候选进入持久通知队列，绑定配置的主人 QQ、账号、身份和发言角色。缺少前端主人 QQ 配置时保留活动候选，不能猜收件人。

“允许自主活动通过 QQ 联系我”独立于“QQ 娱乐互动”开关。按主人授权，沙盒消息全天可主动发送，不受娱乐互动的时段、次数、免打扰、近期输入或未回复门禁限制；你的新消息也不会取消她正在发送的沙盒气泡。她可以积极分享成长、困惑、想法和发现。仍绑定正确 QQ 账号、主人白名单与角色，断线或通道忙时等待可用。当前全局通知走主人私聊，群与空间仍是已配置的 QQ 娱乐渠道。

队列不设每角色待发条数限制；最多保留一小时，不补发过期内容。桥接器先原子领取再发消息；未知结果或崩溃不重新领取。后台显示原文与状态。延后发送只允许交付原草稿，不允许继续调用模型或执行任务。发送前再次检查全局活动/通知开关、角色与项目授权。批准资源不会立即发消息，也不会自动开启活动。
