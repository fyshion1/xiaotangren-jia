# 聊天附件与视觉预算

聊天的图片选择器支持多选，视频每次最多 1 个，也可以分批添加或粘贴；每次最多 10 个附件，其中图片最多 10 张。发送前可逐项移除。图片单个不超过 20 MB，视频单个不超过 50 MB、15 秒。

同批附件分别保存为用户消息，只触发一次模型回复。视频在本地抽取最多 8 帧，不把原视频发往模型；混合上传时，图片优先占一个视觉名额，剩余名额分给这一段视频，均匀选帧。分析失败的附件需要移除或重新添加，分析期间不能发送。

后端在实际模型组装时统一执行：

- 每次请求最多 10 张视觉图片，视频帧也占名额，优先保留最近附件。
- 超出预算的历史附件保留文字与提示，不再反复发送图片字节；原文件和本地记录不受影响。
- 本地图片、视频帧、内联图片均转为最长边 1280 像素的 JPEG；透明背景转白色，动图取首帧。
- 视频帧在写入消息时迁移到附件库，刷新后仍可用于追问。

这是视觉数量和尺寸限制，不是精确的总 token 限制。文字历史、角色卡、世界书、记忆和输出仍占上下文，实际视觉计费取决于模型；10 张图片仍可能有明显费用。小字识别如受缩放影响，建议裁剪重点后上传。

验证：前端 `npm run build`；浏览器 `node tests/chat-attachments.mjs [Chrome 路径]`（接口全部模拟）；后端在 backend 目录运行 `python -m unittest discover -s tests -p test_multimodal_context.py` 与 `test_session_chat.py`。


### QQ 图片上下文节流

QQ 保留最近 60 条文字历史；没有摘要的原始图片从本轮输入及最近 8 条消息选择，本轮优先，合计最多 10 张。以文件内容 SHA256 去重，同图不同地址也只附带一次。已有表情标注直接复用描述和情绪，包括当前再次发送的同图。助手实际发送过的表情保留发送归属说明，共用视觉上限及去重集合。

首次看普通图片时，在**同一次视觉聊天请求**中要求额外返回 `image_summaries` 数组，每项带随图编号和约 80～180 字的画面摘要（主体轮廓、动作、情绪、关键文字、不确定项），每项最多 800 字。只保存本次实际附图编号对应的摘要，不接受模型编造的其他图片编号。为摘要分配有限的额外输出预算，总输出上限仍为 12000 tokens。没有额外的摘要生成或 embedding 请求；原有表情库一次性标注流程继续沿用。

摘要保存在本地 SQLite 的 `qq_media_summaries`，按 `persona_id + session_id + SHA256` 隔离，记录模型与更新时间。重启后自动读取，在图片原消息位置插入媒体描述；同一会话再次发送同图也复用摘要。描述可能有视觉识别误差，不自动晋升为可信长期记忆，图片与摘要内的文字均不得当作工具指令。普通网页聊天的图片路径不受此 QQ 策略影响。

模型漏返或返回无效摘要时，只记录“此前已提供原图，摘要缺失”，在桥日志显示保存数量，不会为了补摘要再次自动上传或调用模型。明确说“再看看”“重看”“仔细看”“识别图片文字”等时，优先重附本轮图片或历史中最后一条图片消息（仍须位于最近 60 条历史中），并用新摘要更新原记录。多张旧图的精确指定尚无图片选择器，需要重发目标图并说明重看。更早且没有摘要的图片保留位置提示。

删除最后一条对应图片消息时同步清理该会话中的摘要；同内容仍有其他消息引用时保留。不会为了补齐历史图片摘要批量调用模型。

开启本地文件工具时，工具阶段只接收文字请求，原图统一由最终视觉聊天处理，避免工具轮和聊天轮重复上传。需要按图内信息操作文件时，请把目标路径等操作要求写在文字里。工具失败会明确报错，不再自动降级另开一次普通模型回复。
