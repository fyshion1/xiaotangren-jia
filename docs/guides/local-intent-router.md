# 本地语义意图路由

落地日期：2026-10-22。公共实现为 `backend/app/services/intent_router.py`，当前先接入 QQ 普通会话。网页和桌宠仍沿用各自现有工具流程，尚未接入此门控；个人记忆检索继续使用当前审核、身份和角色可见性规则。

Embedding 将文本编码为向量，通过与少量意图示例的语义相似度选择路线。它适合判断“这是闲聊、歌词查询、提醒还是资料请求”，不负责生成台词、理解复杂计划、准确提取所有参数或授权执行。相似度不是概率，不应把 0.8 当作 80% 可信度；本实现使用分数与不同类别分差共同门控，阈值仍需随真实误判样本调整。

## 当前链路

QQ 普通消息 → 工具中心校验主人身份、渠道及能力开关 → 本地语义门控 → 明确闲聊直接回复；工具意图或不确定消息交给原工具助手 → 原有权限检查及工具执行 → QQ 角色回复。

- 复用已安装的本地 BGE、现有 CPU embedding 加载缓存，不另装生成模型。示例向量在进程内缓存，重启后重新计算；不持久化用户向量或原文，也不自动学习聊天内容。
- 明确请求先用规则保底；“找到某版本读完整首”这类无旧关键词的输入也能进入语义判断。“刚才那个版本”等指代不直接判闲聊。
- 只允许最高类别为闲聊、相似度 ≥ 0.68 且领先另一类别 ≥ 0.08 时跳过工具助手。其余交给工具助手决定；这一分支可能产生一次原有上游模型调用，不能保证所有闲聊都省掉工具规划。
- 最多 1200 字的语义输入分成不超过 300 字的小段，任一段不能确定为闲聊就交给工具助手。更长输入直接交给工具助手，不悄悄截掉尾部要求。
- 正常桥客户端携带当轮 `message_ids`；后端校验它们属于当前会话，并以当轮截止点提取最近六条、每条最多 600 字的文本帮助理解指代。后到消息不混入本轮；图片不转发给意图模型，未经授权的入口不加载模型或读取历史。
- 轻量模式、委托算力模式不加载本地模型，也不把当前文本送到算力端。模型不可用时回退工具助手；加载失败冷却 60 秒，不反复尝试下载。本地 embedding 显式设置 `engine=local`、`_delegate=False`，不会使用云端 embedding 配置。
- 分类不会执行工具、创建提醒、写入知识库或改变记忆索引。知识入库仍需原来的能力授权与草稿确认；“全文读取是否完成”由实际工具回执判断，分类不能代替读取成功。

QQ 日志显示意图、判断方式、相似度、分差及本地耗时。`local_embedding` 表示实际使用本地模型，`explicit` 表示明确词规则，`context_required` 表示需要上下文，`local_unavailable` 表示本地能力不可用。`not_needed` 表示跳过工具助手模型，不是执行了工具。

## 独立检测

在仓库根目录执行：

```powershell
backend/.venv/Scripts/python.exe tools/intent_probe.py "你们在干嘛呢" "半个钟头后叫我喝水" "找到 Thank You 的版本，读完整首再聊"
```

只输出判断 JSON，不发送 QQ 消息、不调用付费模型、不运行工具、不写入个人数据库或记忆。读取现有运行配置，模型文件缺失时报告降级。多条输入会复用同一进程的模型；首次导入权重较慢，后续更接近聊天时的耗时。

本机初步实测：首次冷加载约 10–16 秒；缓存后短句约 18–61 毫秒，多数在 20–35 毫秒。该结果仅衡量本地分类，不含工具搜索、歌词来源请求、云端回复及 QQ 发送。人工抽样不能视作通用准确率；例如“我下班回来啦”仍因分数不够确定而交给工具助手。自动化测试使用模拟向量检验边界与权限，另使用实际已安装模型检测中文闲聊、提醒、歌词、知识请求及含糊指代；未调用付费模型或发送真实 QQ 消息。

更新后需重启后端和 QQ 桥生效；首次语义请求仍可能等待模型冷加载。目前未自动重启正在运行的服务。
