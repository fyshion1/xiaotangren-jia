# 知识资料与历史陪读

第一版实现日期：2026-10-21。

在「私人空间 → 个人数据库 → 知识资料 · 历史陪读」使用。查看的身份需要与当前使用身份一致；若只是在看另一份身份档案，先点击「成为」。

## 日常使用

1. 在聊天中说「按我的笔记，看看宋代的货币和贸易」，小糖人可以调用资料检索工具，引用笔记出处。可进一步要求展开上下文。
2. 同期比较可以说「查唐朝 618—907 年间，日本和欧洲分别有什么记载，区分明确年代和宽泛范围」。世纪只提供宽泛候选，不能凭范围相交就断言某件事发生于唐朝；同期也不能推导因果。
3. 说「把刚才的想法整理成待核实补充，放到这份笔记里」，模型生成补充草案。在个人数据库的知识资料区刷新，核对目标文档、分类、内容和插入位置，再点击「确认补入正文」。
4. 没有唯一的原文定位文字时，补充放在文末；有定位时放在该文字所在的完整段落后。补充注明北京时间、想法/讨论结论/待核实分类，不改写已有原句。原文已变化会拒绝确认，需要重新读取和提出草案。
5. 「编辑工作正文」可以继续手动整理。下一次检索会检查文件哈希，更新文字索引；不变片段复用向量，新增片段按需编码。「建立／补齐语义索引」可分批补齐全部向量。

补充操作会备份旧正文，在已有文件编辑器的「历史」中查看和恢复。恢复或外部编辑后，下次检索更新索引；旧引文内容或位置失效时提示重新检索，不用旧结果冒充当前原文。

已为当前主人身份导入 7 份资料：高中中国历史年表、中国历史 A/B 合并版、欧洲史 A/B、日本史 A/B。选择一组主资料作为试点，其他 Word 版本可在「导入历史原笔记」中勾选导入。完全相同的源文件不重复导入；同名不同版本保留各自来源，检索时对完全相同的片段合并展示来源，不自动裁定差异对错。

Word 后续变化会显示提示，重新导入不会覆盖已积累的讨论。此时可对照原文件手动整理工作正文；尚未实现 Word 和 Markdown 的双向自动合并。图片保留未转写提示，第一版不做图片 OCR。

## 权限、索引和配置

- 数据库 `backend/data/knowledge.db` 保存资料登记、片段、向量和待确认补充；Markdown 是正文真源，向量可重建。待确认草案自身尚未写入正文，不能删除数据库后期待它自动恢复。
- 每份资料绑定导入时的用户身份。聊天工具继续遵守工具中心的主人和渠道开关；第一版主人资料在其获准聊天渠道中使用，没有额外的逐角色资料授权界面。
- 此功能不把课程资料写入关系记忆池，不要求批准到 `03_AI注入层`，也不将整篇笔记常驻提示词。
- 词项检索使用中文二元字符和英文/数字词项；向量复用项目 embedding 配置，结果用排名融合。年代与地区先筛选，部分年代重叠再降权。当前规模直接在 SQLite 片段记录上打分，未引入独立向量数据库或图谱服务。
- 显式填写开始/结束年代时，未知年代的段落不参与同期筛选。只按“宋代货币”等朝代名称查主题时，允许未标定年代的相关段落参与，避免聊天中刚补入的想法因没有年代标题而永远查不到；界面明确标注“年代未标定”。
- 若向量不可用，查询降级为词项检索并显示状态；未补齐索引时显示部分混合检索。云端 embedding 仅在现有项目明确配置为 cloud 时使用；本次首批索引使用本机 `BAAI/bge-small-zh-v1.5`。
- 聊天能力为 `knowledge_search`、`knowledge_read`、`knowledge_propose`。确认接口只在用户界面提供，不作为模型工具注册。工具结果正文保留于当轮上下文和实时事件，不复制到工具执行日志。
- 本次已为配置中的主人开启上述三项工具，保留原有工具和渠道开关；原设置备份在 `backend/data/knowledge-backups/tool-settings-before-knowledge.json`。

## 开发与验证

核心服务：`backend/app/services/knowledge.py`；工具适配：`knowledge_tools.py`；HTTP：`backend/app/routers/knowledge.py`；界面：`frontend/src/components/KnowledgeLibrary.tsx`。

后端测试：在 `backend/` 运行 `.venv/Scripts/python.exe -m unittest discover -s tests -p test_knowledge.py -v`。覆盖原件保留、表格读取、身份隔离、年代与地区筛选、未知年代不继承、向量缓存、草案确认、冲突、备份、引文转义、手动编辑刷新和工具调用链。

浏览器测试：运行 Vite 后，在 `frontend/` 运行 `node tests/knowledge-browser.mjs`，可用 `CHROME_PATH` 指定 Chromium 路径，`KNOWLEDGE_TEST_ORIGIN` 指定 Vite 地址。该测试隔离挂载组件并拦截全部业务 API，覆盖草案不自动写入、冲突阻止写入、确认后更新、引用链接安全及 1360/390/320 像素宽度；不会向实际资料添加测试想法。

另已用运行中的实际 API 验证首批资料的宋代货币、唐代日本与欧洲同期检索以及引文页面，并在实际个人数据库页面检查检索入口。模型工具循环以模拟模型验证，未向用户真实聊天中发送测试消息；检索命中不代表已完成全部史实核验或回答准确率评测。
