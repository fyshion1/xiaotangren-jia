# 一次性提醒

打开网页聊天「✦ 工具能力」或小窝「工具中心」，勾选「提醒草稿」，开启并保存工具设置。原有设置和工具总开关不会被自动修改，新能力也不会被自动勾选。

在聊天里说「明天下午三点提醒我交材料」。AI 根据当轮北京时间生成草稿；时间不明确时应先追问。然后在工具中心的「我的提醒」核对事项与完整日期时间，点击「确认创建」才会生效。桌宠也能生成草稿，通过「✦ 工具中心」进入同一页面确认。

提醒列表显示待确认、等待提醒、已到时间、已读、已取消和草稿已过期。可以修改或取消未到期提醒；保存修改会返回待确认状态，需要重新确认。到期后点「知道了」标记已读，网页和桌宠会在下一次轮询后同步。草稿最长保存 24 小时，到原定时间也会失效。

沿用原有粉色卡片、主题色和圆角按钮，支持手机、浅色及深色模式。截图：[桌面](../tool-agent-evidence/reminders-desktop.png)、[手机](../tool-agent-evidence/reminders-mobile.png)、[深色](../tool-agent-evidence/reminders-mobile-dark.png)。

## 时间与通知

第一版仅支持一次性提醒，采用北京时间（Asia/Shanghai、UTC+08:00），支持 5 秒后至未来一年以内的时间。后端每 5 秒检查到期状态；网页和桌宠每 5 秒读取未读提醒，可能有数秒延迟。后端需要运行；关闭期间到期的任务会在重新运行后补显，不会丢弃。

网页以站内通知卡片显示，桌宠显示到期提示，并在系统支持时尝试发送原生通知。原生弹出还受操作系统权限、免打扰和应用安装状态影响；站内及桌宠提示可作为确认入口。未读提醒会一直保留，重启桌宠后可以再次提示；这里提供的是持久化待办箱，不承诺跨客户端只通知一次。没有增加 QQ 推送、重复周期、外部日历或系统关机唤醒。

## 执行边界与数据

模型只能调用 `reminder_draft`，属于 SDK 的 `proposal` 风险类型：可保存草稿，不能激活任务；`ToolPolicy.allow_proposals` 默认关闭，草稿工具禁止自动重试。后端仅在已开启的可信网页/桌宠适配器中显式允许；QQ 等既有适配器仍默认拒绝。

草稿按当前主人身份、内容和绝对时间去重，防止重试重复创建；修改后重新生成原事项不会返回错误内容。确认、编辑、取消、标记已读必须经界面 API，并使用 revision 检测冲突；重复确认不会重复安排。请求只可操作当前活动身份的提醒。本地应用既有的单用户信任模型保持不变，身份筛选不是独立的登录认证。

提醒内容、时间、所属身份、来源会话、状态和修订号保存在 SQLite 的 `reminders` 表，重启不依赖内存计时器。提醒本身是用户需要保留的任务数据；工具运行日志仍只存元数据，不复制参数或工具正文。取消不删除历史。列表显示最多 100 条，优先显示到期和进行中的任务。关闭工具总开关仅停止生成新草稿，已确认任务继续有效；需要停止的任务请在列表取消。
