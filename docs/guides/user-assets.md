# 用户角色资源与数据位置

2026-10-24 第一阶段实现。目标是让用户持有的人设和图片独立于主题的安装、停用和卸载，不进行整库搬家。

## 管理入口

设置 → **角色资源**，或 `/#character-assets`。可查看图片的用途、档案引用和文件可用性；选择角色或身份后上传头像、立绘。通用角色编辑器保存本地图片时也使用资源层。当前资源管理的上传、列表和迁移接口限本机管理页面；不改变既有角色编辑器的访问方式。

人设、身份及形态覆盖仍以 SQLite 中保存的档案为准，通过现有角色、身份编辑器管理。未创建另一份会自动覆盖数据库的提示词原稿。最终发给模型的提示词仍由人设、身份、历史、记忆和规则组装。

## 文件和引用

- 数据库：`backend/data/xiaotangren.db`，新增 `user_assets` 资源索引表。
- 角色图片：`backend/data/assets/<SHA-256>.<扩展名>`。按内容去重，保留图片原字节，包括 GIF 动画。
- 档案引用：`/api/assets/<ID>/content`。此接口由本体提供，不依赖主题。
- 迁移前数据库快照：`backend/data/backups/before-character-assets-<指纹>.db`。SQLite backup 后执行完整性检查；相同待迁移档案不重复创建备份。

`app/data_paths.py` 集中本体已有运行目录和私人双库的路径策略，默认物理位置不变。`PERSONAL_DATABASE_ROOT`、`PERSONAL_MEMORY_ROOT` 保留兼容；本次没有增加一个会让现有数据突然消失的新数据根目录开关。

私人知识库仍可放在外部目录，聊天附件、语音模型与角色资源继续分区。这里的“统一管理”先统一所有权和路径策略，并不把缓存、模型、全部文档合成同一种存储。

## 兼容迁移

后端初始化时，先对已有待迁移档案做快照，再处理 `characters`、`profiles` 内的头像、立绘以及嵌套形态覆盖：

1. `/characters/` 默认图片从现有主题、卸载备份或旧前端素材目录复制。
2. `/api/files/` 的本地附件图片复制到用户资源层，不再依赖附件清理生命周期。
3. 内嵌图片 data URL 转存为文件，档案保存稳定资源 URL。
4. 外部 URL、空值和无法找到的源文件保留原值，不联网抓取、不猜测替代图片、不改变角色 ID 和人设。

源文件始终保留。关闭、卸载旧主题前也会执行保存检查；缺失的本地图片会阻止该操作，管理页可重试迁移或重新上传。已经停用甚至卸载的主题，可通过还在本机的原目录或卸载备份恢复素材。新上传的资源不自动删除；未关联文件可在列表中看到，暂不提供自动垃圾回收。

## API v1

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/assets` | 图片清单、档案引用、文件可用性、待转存引用；返回 `api_version: 1` |
| `POST /api/assets` | `{ "data": "data:image/png;base64,..." }`，返回资源 ID 和 URL |
| `PUT /api/assets/assignment` | 将已有资源绑定到 `characters` 或 `profiles` 的顶层 `avatar` / `portrait` |
| `POST /api/assets/preserve-legacy` | 备份并保存旧引用，返回更新数和未解决项 |
| `GET /api/assets/{id}/content` | 读取图片，不受主题开关控制 |

管理请求使用现有本机后台保护与 `X-Exploration-Dashboard: 1`。绑定参数为 `kind`、`owner_id`、`field`、`asset_id`、`expected_url`；当前值已变化时返回 409，避免覆盖并发修改。内容支持 PNG/JPEG/WebP/GIF，校验真实格式、大小和像素上限，不导入 SVG/HTML，不接受任意磁盘路径或远程抓取。列表不返回设定全文。

这是首个用户资源契约，不代表已有完整第三方插件认证或稳定 SDK。桌宠等目前可继续读取角色 API 返回的图片 URL。

## 备份与恢复

资源文件和数据库必须一起备份。已有 `tools/create_personal_snapshot.py` 包含 `backend/data/`，因此会包含新资源和迁移快照；单独导出数据库不能恢复未随包保存的图片。迁移快照本身也不包含附件或资源的文件字节，原素材没有被删除。

恢复应在独立目录中验证，先停写再切换。不要在仍运行的服务上直接覆盖数据库。私人快照不上传 GitHub。

## 当前边界

- 用户已保存的数据与主题的生命周期已解耦；源码里的旧默认模板仍保留主题兼容入口，另已支持独立声明式角色包导入，见[角色包说明](character-packs.md)。本机样包尚未公开发行。
- 角色使用的 Live2D/VRM 模型、音色与第三方素材尚未纳入图片资源 API。
- 本体路径入口已收敛，但插件可能仍有独立的路径约定；尚未实施整个工作区的迁移器。
- 当前提供图片归属、上传及角色包的预览确认导入；支持从本机配置的 GitHub 发行目录下载。未建设公共中心市场，不提供私人档案的一键导出或跨设备自动同步。
