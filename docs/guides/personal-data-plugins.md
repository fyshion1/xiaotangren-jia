# 可选个人资料功能与本体记忆

2026-10-24，依据用户最新决定：记忆是本体完整的默认能力；额外个人档案和个人数据库是可选功能。新用户不安装这两个插件也能聊天、保存历史和使用本体记忆。

## 边界

| 能力 | 归属 | 停用资料插件后的行为 |
| --- | --- | --- |
| 基础用户身份、角色资料、切换身份 | 本体 | 保留 |
| 近期聊天、长期记忆存储、检索、审批、注入与管理界面 | 本体 | 保留，不依赖资料插件 |
| 额外 Markdown 档案区块编辑 | `features/personal-profile/` | 隐藏编辑器，停止该来源读取与注入；文件、原 `inject` 勾选和可见范围保留 |
| 个人文件树、知识整理、资料收录与目录巡检 | `features/personal-database/` | 停止对应管理接口、资料与索引读取、目录巡检、数据库条目注入；原文件和挑选记录保留 |

“隐藏入口”只收起管理面板，来源仍可按既有批准设置参与聊天；“关闭插件”才暂停该来源。修改开关后点“应用修改”生效。重新启用恢复原有文件和配置，不自动批准新资料。

已主动复制到本体长期记忆中的内容属于记忆记录，关闭资料插件不会自动删除或撤回；应通过原生记忆管理另行处理。已完成或正在进行的模型请求也不能因停用而撤回。

## 隐私

- 插件代码与个人数据分离，安装包只含代码，不附带个人文档。主仓库忽略 `features/` 下插件代码及运行期数据。
- 新建额外档案区块默认 `inject: false`。个人数据库条目继续遵守审批、身份挑选与角色可见规则，安装插件本身不等于批准全库进入模型请求。
- 浏览管理面板和本地文件操作不主动执行 AI 整理、付费 embedding 或全库上传。主动使用 AI 整理、云端嵌入、知识工具或批准聊天注入时，所选内容可能送往配置的模型服务；“存在本机”不等于“绝不发送”。
- 未安装/停用插件时，界面不加载相应文档，后端也检查来源开关。该检查是功能启用边界，不是完整第三方插件沙盒或多用户认证；此项目仍采用现有本机应用身份机制。
- 当前只拆前端管理功能和宿主可用性检查，通用文档存储、审批、身份与 HTTP API 留在宿主。未迁移私人资料目录、未导出个人文档，也未重写原有注入勾选。

## 本体宿主契约 v1

`GET /api/personal-space/panels` 返回 `api_version: 1` 及固定槽位 `personal-space.profile`、`personal-space.database` 的安装、兼容、启用和隐藏状态，不返回文件名或文档正文。

两个插件以 `plugin.json` 声明 ID、`kind: personal-space-panel`、`host_api: 1`；宿主在构建时选择真实模块或空实现，运行时再核对可用状态。编辑器只使用宿主传入的类型化 API facade，不接收数据库或文件系统句柄。知识管理和嵌入配置面板仍复用宿主组件；这不是任意第三方插件的动态注册系统。

资料 API 保留既有路径：个人档案 `/api/self/...`，个人数据库 `/api/personal-db/...`，知识资料 `/api/knowledge/...`，巡检 `/api/patrol/...`。相应插件缺席或关闭时返回 409，且不会为了渲染空状态而扫描资料目录。

## 安装、停用与卸载

两个插件已分别提交并推送至 `fyshion1/personal-profile` 和 `fyshion1/personal-database` 私有仓库，尚无公共发行地址。它们不随主仓库提交，公开发布前需单独整理版本与许可。

- **开关/隐藏**：应用后运行时更新面板，通常不整页刷新。
- **安装/卸载/恢复**：改变编译模块是否存在，开发服务重载；生产部署重新构建前端。卸载将插件代码移至已有卸载备份，用户资料不随之移动或删除。
- **重新安装**：读取同一宿主数据与稳定身份 ID；不复制生成另一套私人库。

## 记忆扩展方向

原生记忆不再按早期方案拆成必装插件。用户确定本体按 Apache-2.0 开源的方向，使用者可以改造本体；未来也可建立可替换的记忆提供者接口，但目前尚未实现通用运行时后端热替换和数据自动迁移。第三方素材与插件的许可单独核对，本轮未写入新的授权声明。
