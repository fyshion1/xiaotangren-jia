# 私人空间的模块边界与个人数据管理

2026-10-24。依据现有代码与用户最新决定更新：记忆作为本体默认能力，个人档案和个人数据库作为可选插件。本轮不移动私人资料目录。

## 建议

将私人空间视为本体提供的身份与记忆入口，仅额外个人档案和个人数据库作为可选面板。用户数据不属于任何安装包。先拆界面和调用契约，再逐步拆服务实现，最后在确有必要时迁移数据；不按页面名称把数据库和文档直接搬入插件目录。

## 当前代码与职责

| 当前内容 | 已验证位置 | 建议归属 |
| --- | --- | --- |
| 身份档案、当前身份切换 | SQLite `profiles`；`routers/profiles.py` | 本体：身份 ID、基础资料、切换、访问范围 |
| 角色头像、立绘与用户资源 | `services/assets.py`、`backend/data/assets/` | 本体：资源登记、引用检查、备份 |
| 自我档案的 Markdown 区块 | `services/self_profile.py`；`backend/data/self_profile/<身份>/` 与 `_shared/` | 可选“个人档案”面板；文档仍在用户数据区 |
| 事实与知识资料 | `routers/personal_db.py`；`PERSONAL_DATABASE_ROOT` 或项目根 `个人数据库/` | 可选“资料库”管理器；保留外部路径及跨项目使用 |
| 正式记忆与待审核内容 | `services/memory_workflow.py`；`PERSONAL_MEMORY_ROOT` 或 `个人记忆库/` | 本体：记忆存储、检索、审批、注入和管理界面均保留 |
| 巡检、成果收录 | `PatrolPanel.tsx`、巡检/收录服务 | 个人数据库的可选能力；停用数据库后停止任务及面板 |
| 画廊、聊天、附件 | 现有 SQLite 与媒体目录、`GalleryGrid.tsx` 等 | 本体持久数据服务；具体整理工具可选 |

现已为两个管理面板提供固定宿主槽与 v1 类型契约；这仍是可信本机插件接入，不是任意第三方注册或权限沙盒。记忆界面继续由 `HomeView.tsx` 原生挂载。

## 拆分次序

1. 建立私人空间面板注册契约：稳定 `panel_id`、所属插件、标题、顺序、所需权限和身份上下文。本体保留身份切换与空状态，各插件注册面板，未安装时不显示占位业务内容。
2. 先提取“个人档案”面板：改走本体提供的区块读写契约，保持原文件路径和 ID。再提取个人数据库。记忆工作台留在本体，不继续拆分其提示词、向量索引及审批流程。
3. 个人数据库停用时停止巡检任务、管理接口、资料索引与数据库注入条目读取，文件和挑选记录保留；普通聊天记忆不受影响。
4. 个人档案插件管理额外 Markdown 区块；停用时暂停来源读取和注入，保留已保存的 `inject` 与角色可见范围，重新启用时沿用。新建区块默认不注入；个人数据库停用也停止该来源的读取。隐藏入口只收起面板，不暂停来源；关闭插件才暂停。两者都不改变原生长期记忆。
5. 增加按身份的数据清单与备份/恢复预览，再考虑数据目录重组。预览显示数量、资源依赖、目标位置和冲突策略，不展示或上传私人全文。

提取后的插件只管理自己的偏好与任务状态，不直接读写 SQLite、不接管整个私人资料根目录。通过本体 API 获取被授权的数据，权限收回后接口和后台任务一并受限。当前尚没有完整第三方插件授权体系，上述为后续契约要求。

## 数据布局原则

- 身份、档案、会话和资源保留稳定 ID；文件引用改为资源 ID/API，不绑定代码目录。
- 文档保留人类可读格式，原 DOCX、Markdown 等不因插件化被覆盖；向量索引是可重建派生数据，不作为唯一原件。
- 用户数据目录与 `features/` 安装目录分离。个人档案、知识、正式记忆与待审草稿各自标明类型，逻辑统一管理并不等于强制物理合并。
- 现有外部资料库继续使用环境变量配置，跨项目资料不强制搬进本项目。
- 卸载插件保留全部私人资料，清理数据必须是独立、明确的操作；备份必须同时覆盖数据库、文档与图片。
- 发布本体或插件只包含通用代码、空模板与测试数据，不把个人档案打成默认示例包。

## 首个拆分模块的验收

在临时数据副本验证：启用后可查看/编辑本身份数据；跨身份访问受实际规则限制；关闭后面板与任务停止；卸载后资料仍在；重装重新关联原资料；升级不覆盖个人编辑；备份恢复后 ID 与图片引用不变。真实私人库迁移前另外备份并演练恢复，不在这轮配色和插件开关调整中顺手移动。


## 本轮落地边界

- `features/personal-profile/`：额外档案区块编辑器；宿主注入明确的 HTTP API facade，不给予数据库或磁盘句柄。
- `features/personal-database/`：个人文件管理面板，使用宿主资料 API；知识整理、嵌入配置与巡检面板按该插件状态挂载。
- 插件缺席时本体可构建；停用管理面板通过运行时元数据更新，不因两个插件的开关重建整页。安装/卸载改变编译模块可用性时，开发服务重载；生产构建需重建。
- 后端文档存储、现有 API、身份与审批规则仍属于宿主通用数据服务，并有个人数据库可用性检查；未宣称所有后端资料实现已经移到独立仓库。
- 个人数据库缺席/停用时，不扫描资料目录，不读知识索引，不将已挑选数据库条目加入模型请求；重新启用后沿用原文件和挑选记录。
- 新用户不安装资料插件也有完整的基本聊天与原生记忆；装插件不自动执行 AI 整理、付费 embedding 或全库上传。已批准参与聊天的内容会随请求发送给配置的模型，不能将“文件在本机”误称为“绝不发送”。
- 用户确定本体按 Apache-2.0 开源的方向。第三方素材和插件许可分别核对，不因本体许可自动重新授权；本轮未执行许可证文件发布。
- 记忆替换保留为后续提供者接口方向：用户也可直接修改开源本体。目前不声称已经实现通用的运行时记忆后端热替换或数据自动迁移。
