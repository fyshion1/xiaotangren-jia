# 私人版工程改进与未来公共版路径

记录日期：2026-10-19。依据用户本轮授权及《发布与知识产权跟进.md》。

## 目标与边界

项目首先服务本人长期使用，同时积累可解释、可验证的求职作品。私人版保留现有体验；未来公共版复用核心能力，通过独立入口、权限、存储与策略适配。两版不长期维护两套独立源码，不以立即公开、运营或重写 Go 为目标。

当前其他对话正在修改语音代码。本轮不编辑语音实现及其共用配置，不提交、覆盖、暂存或回滚其他工作的修改。源码快照可能包含语音开发的中间状态，不代表其已通过验证。

## 可执行顺序

| 阶段 | 交付 | 验收依据 |
| --- | --- | --- |
| 1：保护现场 | 仓库外本地快照、Git 状态与提交号、备份清单、恢复说明 | 压缩包校验、内容哈希校验、数据库备份完整性检查；不改私人数据 |
| 2：记忆评测 | 先人工编写 30～50 个合成案例；独立运行器、逐条结果、评分与版本信息 | 覆盖事实编造、约定误判、纠正、权限过滤、检索遗漏与无关注入；真实运行结果可复现 |
| 3：调用追踪 | 请求 ID、功能、模型、提示词版本、耗时、失败分类、重试与用量记录 | 能定位一次失败；默认不保存密钥及私人原文；用量缺失明确标记 |
| 4：本地开发控制台 | 评测发起与比较、调用记录、版本记录 | 后端持久化运行状态，关页面不丢任务；继续保留用户侧记忆确认 |
| 5：公共版适配准备 | 可配置数据路径、显式初始化、清晰的能力接口 | 隔离测试不读写私人数据；现有私人启动方式仍可用 |
| 6：未来公共版 | 独立入口、登录、数据归属、受保护附件、配额、安全策略、管理员端 | 两个真实用户并发互不影响；公共入口不注册本机控制或明文密钥接口 |

阶段 2 以后是后续路径，不在本轮直接开始建设。先依据阶段 1 的结果推进，不设发布倒计时。

## 评测建设原则

软件回归测试与真实模型评测分别记录。初期使用合成资料，不把私人聊天直接上传到 CI。记录数据集版本、Git 提交和工作区状态、模型、参数、提示词版本、实际输出与失败原因。关键隔离失败单独设门槛，不用平均分掩盖。真实模型评测手动触发并设置调用预算，先使用 CLI/结果文件，再做界面。

## 代码与版本管理

- 一个主体仓库：共享核心、私人入口、未来公共入口；短期功能分支完成后合并。
- worktree 用于较大改造的工作目录隔离；它不会自动隔离数据库、环境变量、端口或外部资料目录。
- 私人日常环境固定在已验证版本，公共开发环境使用独立数据。两版可以从不同提交发布，无须维护永久分叉。
- 当前工作区尚有并行开发，不将现场快照称为稳定发布版。待相关开发结束并验证后，再整理提交、标记版本及建立 worktree。
- features 下各功能目前是独立仓库，继续通过 HTTP 契约接入，不为两版适配强制搬回主体。主体快照与各功能的 Git 历史不是一回事。
- GitHub 后续先增加离线 Actions 检查和 PR 审阅记录；部署、公开仓库和许可证另行决定。

## 第一阶段备份范围与恢复

使用 tools/create_personal_snapshot.py 创建仓库外 ZIP。包含主体 Git 可见源码（已跟踪与未忽略的新文件）、各独立功能 Git 可见源码、主体运行数据、私人双库，以及本地 .env。排除可重新下载的 backend/data/models 与 backend/data/tts；其他 Git 忽略文件不保证收录。快照含私人资料和可能的密钥，仅限本机保管，不上传 GitHub。

SQLite 使用只读源连接及 backup API 生成一致性副本，不直接复制运行中的 WAL 数据库。其他文件采用逐文件读取，记录读取期间变化；运行中的不同文件与数据库不保证跨文件事务一致。源码也可能是并行修改中的状态。若需严格可恢复的稳定发布基线，应在开发及写入暂歇后重新快照并验证。

恢复时先解压到一个新的空目录，依据 manifest.json 核对范围。不要直接覆盖正在使用的目录或数据库。安装依赖、准备被排除的模型，检查 .env 与私人资料路径指向恢复目录，用不同端口启动验证后再考虑切换。恢复演练暂不启动真实服务，避免后台任务写入现有资料。

快照附有源码提交号、主体及功能仓库状态、文件 SHA-256、排除项和缺失项；它不包含完整 Git 历史，也不是数据库与附件跨文件一致性的保证。
