# 记忆负担优化（2026-10-20）

## 携带方式和预算

个人记忆库正式记忆沿用 inject/core 存储，界面明确三种方式：按需召回（默认）、常驻（预算内优先）、暂不注入。编辑记忆时选择；原有开关和配置兼容，不迁移已有内容。普通相关检索最多 6 条。个人记忆与个人数据库各自最多 1600 字符，新增共享正文预算 2400 字符，防止两套资料叠加。预算不包含包装标签、当天经历、角色设定、聊天历史，也不是 token 精确上限；常驻不是突破预算的保证。

## 自动候选 24 小时过期

只对本次升级后由每日事件整理新生成的个人记忆候选设置 expires_at，按首次生成起满 24 小时计算，不按午夜切换。后台补充不会延长。读取时判断过期，退出待审核列表，显示在“已过期候选”；不需要模型调用或常驻清理任务，重启后依然有效。文件、详情和证据不删除。

手动添加、手动保存修改、手动保留待审、手动恢复的候选不会过期。旧候选不追溯过期；个人数据库中的事实草稿、任意手写文档不属于这次个人记忆候选的过期范围。已批准记忆不自动过期。恢复入口会明确设置“保留待审”。

## 手动事件整合

在 03 勾选 2～20 条未被整合的正式记忆，点击“AI 整理为一件事”，确认会消耗模型 token 后，产生保护不过期的待审草稿。草稿可编辑、批准或拒绝；批准前原条目仍照原设置生效。若原条目在模型调用期间或批准前修改、归档、被另一份整合取代，操作拒绝，不以过期版本覆盖。

只允许相同身份、角色集合、可见范围、功能归属，保留所有来源和证据。模型负责摘要与来龙去脉，不自动判断扩大隐私权限；资料不构成同一件事、返回无效内容时不修改原记忆。

批准整合草稿后，用新正式文件中持久化的 replacement_committed/integration_records 派生原条目的 superseded_by，阻止原碎片重复注入；不逐一删除或改写原文。关闭整件事注入或归档整件事不会自动恢复旧碎片，以免意外再次透露内容。已整合原条目仍可查看和编辑，但不会因为重新打开旧开关恢复召回。若修改了原事实，应重新整理最新版本；本轮未提供撤销整合的一键功能。

POST /api/memory-workflow/integrate：persona_id、records[{id,revision}]、可选 base_url/api_key/model。只有显式手动调用才运行整理模型，默认 max_tokens=2400；输入上限 24000 字符，生成正文与详情合计最多 1500 字符。原有 /merge 是旧待审核候选的文字合并，不替代此接口。

## 自动整理合批与费用

2026-10-21 流程调整：03 不再要求手动多选已批准条目，改为“一键整理待审记忆”。POST /api/memory-workflow/organize 只需 persona_id 与可选模型配置；服务端读取未过期、未整合的待审短句，按秒级时间排序，一次模型调用按事件关联分组。不同范围、角色集合、插件归属不能合并；不相关短句保留并可直接批准。已生成且仍待审的草稿引用不重复整理；原短句仍可直接审核，但会使引用旧版本的草稿失效。草稿批准后原短句保留在文件中并退出待审列表，禁止再次批准。最多100条/24000输入字符，超限明确报错、不静默截断。模型失败或不合法分组不采用结果。旧 /integrate API 保持兼容。

网页统一入口、桌宠、QQ finish 的自动整理按身份+会话短时间合批：安静 30 秒后运行，连续聊天最多等待 120 秒。处理当前当天新增/修改消息；已有成功批次保持增量去重。同一事件已有待审核候选可补充，用户编辑/批准/拒绝/过期后不覆盖。

网页统一入口现在会把界面设置的 xtr.memoryModel 传给服务端，留空仍沿用该轮模型。手动当天重整和手动事件整合不等待合批。兼容的旧非统一聊天入口仍走原来的直接整理路径。自动整理会调用模型，输入/输出/实际图片均可能计费；一次合批也可能分成多次模型请求，max_tokens=2400 是每批输出上限而非实际消耗。自动过期、预算筛选、当天事件确定性投影不调用生成模型；语义检索若使用云端 embedding 则仍有其费用。

合批队列当前是进程内优化，不是持久化任务系统：停止或重启会取消等待任务，原聊天一直先落库，可通过“重新整理当天”补齐；不同后台 worker 之间不共享防抖队列。既有每日整理并发控制/文件锁仍为进程内，不声称本次解决了遗留文件层跨进程事务。未自动调用模型迁移旧资料，未改动真实插件偏好。
