# 公共插件市场与个人自用方向

日期：2026-10-24。来源：用户对公共插件市场、商用改造及云部署边界的连续确认。本文件记录产品约定及后续实施范围，不表示市场或相关接口已经实现。

## 产品约定

- Shionarium 优先服务个人自用，打磨本地启动、聊天、原生记忆、插件安装与更新。基础聊天和记忆不依赖额外安装插件。
- 允许别人修改、商用并自行改造成云端服务；不增加专门阻碍云部署的设计。正式许可证文件及第三方授权范围仍须另行落实，不以本文替代许可证。
- 多租户、计费与运营后台不是当前开发目标，由实际需要者适配。项目自身未来也可能云部署，保留迁移空间。
- 本机优先不等于云端已可安全上线；现有本机信任假设不能直接当作公网访问控制。

## 工程边界

1. 服务地址、持久数据目录、模型连接与部署参数逐步配置化；本机地址可以作为默认值，不把私人绝对路径写入公共实现。
2. 桌宠、浏览器扩展、本地文件等能力声明其运行环境；缺少它们不阻止核心聊天使用。不为未来云端需求提前整体重写。
3. 插件通过明确的宿主契约接入，逐步减少对内部文件、数据库表和安装目录的直接依赖。记录兼容版本，保留既有数据迁移路径。
4. 有现成身份与资源标识时沿用；新增接口明确作用范围，不新增无必要的唯一用户假设。具体认证与隔离在云部署实施时验证。

## 公共插件市场第一版方向

- 本体提供浏览、搜索、详情、安装与更新入口；公开目录与插件文件分开托管。
- 初步采用公开 GitHub 目录仓库登记元数据，各作者通过固定版本的 Releases 分发安装包，通过 Pull Request 投稿。
- 默认官方目录，保留本地安装与自定义来源，不强制登录，不绑定官方分发服务。
- 展示功能插件、主题、角色包及语音组件；分别说明安装方式、运行条件、依赖和授权。
- 元数据包含唯一 ID、作者、版本、内核兼容范围、许可证、来源、下载地址、校验值与所需能力。检查失败不安装，不直接执行目录里任意安装命令。
- 安装与更新需用户主动触发；显示是否需要重建前端、重启后端。当前加载方式仍有此限制，不承诺热安装。
- 保留旧版本以便安装失败恢复；遵守已有开关「应用修改」机制，区别关闭与隐藏入口，卸载不静默删除个人数据。
- 可提供安装组合降低上手成本，先列明所含插件、下载量和运行条件，由用户选择，不把扩展变成基础聊天必装项。

## 发布与验收顺序

1. 整理市场元数据格式及最小插件开发示例，结合现有插件验证兼容和安装生命周期。
2. 实现目录读取、列表、详情与明确的加载失败反馈，再接入安装、更新与失败恢复。
3. 用独立测试环境验证首次安装、更新失败、兼容拦截、关闭后应用、重启、卸载和用户数据保留。
4. 单独确认哪些仓库与素材公开，再创建或发布公共目录；现有私有插件不能自动转公开。
5. 正式发布前落实本体和各插件的 LICENSE、必要归属说明及第三方素材授权。代码、角色素材、字体、模型和用户数据不混用一份授权结论。
