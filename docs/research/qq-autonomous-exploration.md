# QQ 自主活动：B 站首轮接入

后续实现已扩展项目、后台审批、只读网页与条件启用的容器工作区；当前使用方式和未完成项见 [小工作室说明](../guides/exploration-workshop.md)。下文保留首轮接入背景。

2026-10-19。已实现受控工具活动；不开放任意代码执行，也不把工具白名单称为操作系统级隔离。

## 小糖人现在能做什么

每次随机机会由一位当前在场角色选择：安静跳过、说几句感叹/轻轻吐槽、申请找 B 站候选、保存需求文档草稿、请同一个已配置模型给一次文字建议。草稿不会安装插件、执行命令或更改代码，顾问没有工具和递归指挥能力。

B 站仍使用独立 `bilibili-scout` 的窄适配器：固定读取公开热门列表，按已有口味、排除项和角色本次兴趣排序，最多返回 3 条标题/简介。不是任意搜索，不登录、不读取浏览器、不下载/观看视频，只分享程序构造的官方 BV 链接。模型提供的兴趣只作排序文字，不成为 URL、路径或命令。

一期运行路径：可信定时器 → 固定身份/角色 → 统一计量模型 → 六种结构化意图 → 受控工具或固定目标发布。`browse` 在工具运行时白名单内执行；`document` 仅写 SQLite 草稿；`consult` 只能经同一计量入口调用同一模型。未知意图拒绝，不自动修复重试。

## 开启与查看

在小窝的 QQ 桥设置开启“偶尔主动来找大老大”。沿用已有 QQ 账号、主人绑定和角色选择；默认总开关仍关闭，不凭模型输出猜收件人。

新增“自主活动”设置和记录面板：每次/每日 token 总预算、主动群号、空间开关与可见范围；面板展示输入、输出、已用/预留、B 站发现、需求草稿、顾问建议、分享候选和待同步记录。分享候选不代表已经发送，QQ 仍以实际送达回执保存聊天。

修改注册字段按原机制最多约 30 秒同步。代码更新需要重启后端与 QQ 桥进程；前端需加载新版本。

## 预算与停机

默认单次 12,000、每日 24,000 token；所有角色、私聊、群与空间共用每日额度。每个请求先原子预留，再按供应商返回的输入＋输出结算：

- 每轮重复上下文、角色资料、结果回填、顾问问题和答案都计入，不按循环次数替代用量。
- 请求前采用完整 messages 的 UTF-8 字节数＋512 协议余量＋最大输出作为保守预留。常规单次输出最多 600，顾问最多 400。
- 缓存 token 仍包含在输入里；reasoning/cache 明细不再次相加。支持 `prompt_tokens/completion_tokens` 与 `input_tokens/output_tokens`。
- 缺失、格式错误、总量不一致、超时、取消或进程崩溃造成的未知用量，保留预留并停止当天自主调用。实际超出预留时记录实际用量并停止；恢复按钮不能绕过不确定用量。
- 一次任务最多 6 次模型调用、10 分钟；全局最多一笔模型请求在途。轮数和期限只是额外保护。
- 剩余预算装不下下一次请求就不发起；没有“预算外再总结一次”。重启不清账，跨北京时间日期才获得新的日额度；旧任务不能跨日续跑。

这是应用层的保守预算控制，不是供应商账单硬限额。不同 tokenizer/服务商计量可能使估算失准，已发出的请求也无法保证立刻终止计费。应结合供应商账户额度使用。

自主活动的记忆召回禁用 embedding 模型，只用已有审核、身份、角色与来源权限过滤后的关键词召回；发送结束不触发额外记忆整理模型。用户后续主动发起的聊天/记忆整理属于现有独立流程。

## 节奏与分享范围

- 默认北京时间 10:00–23:00、间隔 90–180 分钟，每天最多 3 次探索机会，skip/失败也占机会。
- 所有渠道共用已有主动发送日上限，默认 3 轮；30 分钟内主人说过话不发，主人未回复当天不追发，重启不补发过期消息。
- B 站最多分享 1 次/天；同一发现只发一个渠道。空间额外最多 2 条/ISO 自然周。
- 主人私聊或白名单群里的消息会使旧主动计划失效。QQ 中“今天别打扰我”或 `/proactive pause` 暂停本地当天主动联系，“可以来找我了”或 `/proactive resume` 恢复。
- 面板“今天先休息”停止本体当天自主调用与待发布候选；已发送内容不能撤回。面板恢复不会重置账本，也不替代 QQ 端的本地暂停/恢复命令。

渠道由模型在可信程序授予的列表中选择，QQ 号、群号、空间权限始终由程序填入。目标/角色/身份/设置发生变化会放弃候选。

| 渠道 | 条件 |
|---|---|
| 私聊 | 绑定的主人和账号，沿用原白名单与静音规则 |
| 群 @ | 设置唯一群号，仍需在现有群白名单，网关能确认主人为群成员，角色在当前群阵容内；使用原生 `at` 段 |
| 空间 | 单独开启，默认仅自己可见；只能选仅自己、仅主人、好友可见，不支持默认公开 |

只要本轮可能分享到群或空间，模型上下文便不注入私聊、用户档案、私密人设字段、长期私密记忆或表情库。只提供角色名、性格/兴趣字段、公开候选及本轮产生的草稿/建议。失败不跨渠道兜底，不扩大可见范围。

SnowLuma 本机实现的 `send_qzone_msg(content, images?, ugc_right?, target_uins?)` 支持空间发布。网关默认 `ugc_right=1` 是所有人可见，发布器永远显式传 64、16 或 4；16 时固定 `target_uins=[主人QQ]`。一期不传 images，不发视频文件。安装代码已核对，真实账号发布能力需要启用后实际观察，不通过测试真实发帖。

外部发送前先持久化尝试记录并消耗频率额度；超时或未知结果不自动重发。QQ 送达回执只重试入库，不重发 QQ。空间成功回执以活动事件归档；失败或未知留在桥的 `proactive.json`，不冒充已送达。

## 记忆和存储

预算、调用状态、草稿位于本体 SQLite 的 `exploration_*` 表。文档是数据，不是可执行文件，也没有模型可指定的宿主路径。

实际 B 站读取、需求草稿按当前 [共享活动契约](../integrations/feature-memory-api.md) 保存 `role=activity`、固定 persona、单个实际角色、稳定事件编号与原发生时间。来源 `qq_bridge` 不决定隔离；禁收时待办保留，恢复后按原身份补交，不能伪装 core，也不恢复已删除原文。没有自动提升为可信长期记忆。

## 下一阶段的真正可执行工作区

如果以后让她自己开发小工具，必须先加入独立系统隔离环境、固定挂载工作区、网络出口代理和资源限制。宿主源码、QQ 凭据、浏览器 Cookie、模型密钥、本机 API 和局域网不能直接进入该环境。

未来的子模型、代码代理和图像模型必须接入同一预算代理，不能让子进程自带密钥另开账本。需求草稿成为提案，经过既定策略才能转为执行；新工具不能由模型直接注册到宿主白名单。当前没有提前开放这部分能力。

## 离线验证

普通 QQ 聊天另有慢上游诊断修正：上游读取等待 300 秒，后端整轮（含协调等待/格式修复）硬期限 360 秒，桥等待 390 秒。普通模型请求不会因网络失败自动重试；总期限取消会释放协调锁，但无法保证供应商停止计算或退款。桥输出开始处理/模型返回耗时，后端按连接超时、读取超时、读取中断、协议异常区分，并记录异常类名，不记录异常正文/密钥。这不是持久化任务队列，进程退出仍不能领取旧请求结果。

`backend/tests/test_exploration_budget.py`、`backend/tests/test_qq_conversation.py`、`features/qq-bridge/tests/test_proactive.py`、`frontend/tests/qq-exploration.mjs` 覆盖预算、并发、未知用量、身份/渠道限制、公共上下文、草稿/顾问、来源禁收恢复、原生 @、空间权限/失败不重发及界面安全展示。所有测试不连接真实 QQ、不调用付费模型、不发布真实空间。
