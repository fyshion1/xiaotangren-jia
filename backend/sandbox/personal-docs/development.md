# 开发与适配规范

1. 先写目标、验收条件、范围和已有权限，再实现。主人聊天可以交办任务，不能批准项目工具或扩大额度。
2. 用 reference 列出并读取 /reference 中实际可见的源码，核对真实接口；只读快照可能不包含配置或私密文件，不假装知道缺失部分。
3. 主项目是 FastAPI 后端与 React/TypeScript 前端；项目实现应遵循被修改模块的实际类型、错误处理、来源归属和接口约定。不要凭空假设接口存在。
4. 通过相对路径在获批工作区写文件。代码执行仅通过 execute 或 agent，不执行宿主命令，不读取密钥，不访问 Docker socket、后台审批接口或本机服务。
5. 缩小改动范围，不顺手重写其他模块。写下涉及的接口、输入、输出、失败路径和兼容行为。数据访问先按用户身份和角色过滤，再分页或召回。
6. 用真实执行结果验证有意义的行为：正常路径、权限隔离、重启接力和失败处理。没执行的测试标为未执行；顾问建议、模型输出和代码草稿都不是测试通过。
7. 工具调用计入同一钱包与项目账本，不能自行开不计量的模型或改预算。上游失败停下；不反复重试、申请或循环同一动作。
8. 交付时报告修改文件、验证证据、限制和下一步。产物留在工作区，由主人在前端审批需要的后续操作；不擅自把实验代码应用到本体。
